RV（敵対レビュー）の実行手順。`docs/20-開発ハーネス.md` §3（敵対レビュー）・§4（RV 台帳）が正典——
本スキルはその型を機械化した入口であり、判断基準（3 分類・重大度校正・目安巡数）は正典側にある。

## 前提

- レビューは作業ツリーから切り離した worktree で行う。コミットされていない変更を混ぜない。
- レビュアーは対象を読み取り専用で扱う（作業ツリーを変更しない）。
- 続き実行には頼らず、毎回新規に起動する。前巡の文脈は台帳で渡す。

## 手順

**① 対象を worktree に出す**

```
git worktree add --detach tmp/worktrees/rv-<name> <sha>
```

`<sha>` はレビュー対象のコミット（またはブランチ）。`<name>` は台帳・出力先と揃える短い識別子。

**② プロンプトを組み立てる**

```
.claude/skills/rv/scripts/rv_prompt.py \
  --target <git 範囲または SHA> \
  --intent "<ユーザーの意図・完成形の要約>" \
  [--proposal <設計の裁定をまとめた文書のパス>] \
  [--ledger <RV 台帳ファイルのパス>] \
  [--round <n>] \
  [--premises "<前提。既定は閉域 LAN・最大 20 人程度・単一 worker>"] \
  [--focus "<レビュアーに確認してほしい事項>"] \
  [--scope "<対象ファイルの説明>"] \
  [--worktree <①で出した worktree のパス>]
```

標準出力に日本語の定型プロンプトが出る（同じ引数なら同じ文字列＝決定的）。`--ledger` を渡すと台帳の
全文が同梱され、「先に読むこと。受容・却下済みは新しい事実がない限り再指摘しない。再指摘するなら
『台帳 #n に対して』と番号を付けて根拠を示す」という定型文が自動で入る——前巡の文脈を続き実行なしで
引き継ぐための唯一の経路なので、2 巡目以降は必ず渡す。`--intent` は必須引数——依頼者（この会話）にしか
分からない「完成形の要点」を短く要約したもので、レビュアーは会話の文脈を見られないため毎回書く（省略
不可）。

**③ レビュアーを実行する**

- 環境に `codex` があれば Codex CLI（既定のレビュアー・gpt-5.6-sol 系のモデル指定は呼び出し側の判断）:

  ```
  .claude/skills/rv/scripts/rv_prompt.py --target <sha> --intent "<意図要約>" [--ledger ...] \
    | .claude/skills/rv/scripts/rv_codex.sh -C tmp/worktrees/rv-<name> -n rv-<name> [-m <model>]
  ```

  Codex は自律実行に時間がかかるため、バックグラウンド実行を推奨する（呼び出し元が長時間ブロックしない
  経路で起動する）。`codex` が無い環境では `rv_codex.sh` は exit 2 で案内を出す——その場合は次の Claude
  経路を使う。

- `codex` が無ければ Claude 実装（`adversarial-reviewer` エージェント）:

  `rv_prompt.py` が出した文字列をそのままそのエージェントへの依頼文として渡す。レビュアーの役割は
  実装（Codex／Claude）によらず同じ入出力契約（`docs/20-開発ハーネス.md` §2・§3）で完了できることが
  条件——結果の扱い方（④以降）はどちらの経路でも同じ。この経路は cwd が自動で worktree に切り替わら
  ないため、`rv_prompt.py` には `--worktree tmp/worktrees/rv-<name>` を必ず渡す（Codex 経路は
  `rv_codex.sh -C` で cwd が worktree になるので任意）。

**④ 結果を台帳へ追記する**

レビュー結果（`[高/中/低] ファイル:行 — 症状 — 再現 — 最小修正` の一覧と「クローズ可／要修正」）を
台帳ファイル（`<対象名>.md`、無ければ新規）へ追記する。置き場所とサブディレクトリ名はプロジェクトの
規約に従う（本体の内部運用では、公開版に含めない非公開ディレクトリの `rv` 以下へ設計裁定文書ごとに
1ファイル置いている）。台帳の列・分類・クローズ条件・行の雛形は同じ場所の
[LEDGER_TEMPLATE.md](LEDGER_TEMPLATE.md) を使う。指摘を
採用したら、まず是正コミットを作り、**その後に別コミットで**台帳へ SHA を書く（同一コミットには
入れられない——是正の SHA を台帳が指すため）。

**⑤ 次巡（要修正のとき）: 是正コミット後、レビュー用 worktree を是正後の SHA へ更新**

```
git -C tmp/worktrees/rv-<name> checkout --detach <new-sha>
```

`<new-sha>` は是正コミットの SHA。更新してから②へ戻る（`--target` は更新後の SHA を指定する）。

**⑥ worktree を消す（クローズ後）**

```
git worktree remove tmp/worktrees/rv-<name>
```

未処理の指摘が残っている間は消さず、次巡のプロンプトに台帳を同梱して②からやり直す。クローズ条件
（指摘なし、または残る指摘がすべて受容記録）に達したら消してよい。

## 引数・選択の要点

- `--target`: 必須。`git show`／`git diff` で解決できる範囲（`HEAD`・SHA・`abc123..def456` 等）。
- レビュアー選択の基準: 環境に `codex` があれば Codex、無ければ Claude（`adversarial-reviewer`）。
  どちらを使っても同じ台帳運用（③④）で完了する。
- 「台帳を先に読ませる」「番号付き再指摘」の定型文は `rv_prompt.py` が `--ledger` 指定時に自動で
  組み込む——呼び出し側が毎回手で書く必要はない。
