個人設定

自分にだけ効く設定です。チャットに使う AI・許可されている場合は自分の API キー、 回答方針、表示の好みを設定します。API キーは画面に再表示しません。 使えるモデルの一覧や機能ごとの AI の割り当ては管理者の「システム管理」で管理します。
この画面の使い方 →
チャットに使う AI（既定）
チャットの回答に使う頭脳の既定です。 チャット画面のメニューからも変更できます（この既定そのものが書き換わります）。
許可されている場合は、自分の API キーを下の「API キー」で設定できます。
下調べ（資料の検索）に使う AI
資料をたくさん読む「下調べ」だけを安い AI に任せ、 最終的な回答は上で選んだ AI が作ります（費用の節約）。 資料調査は読む量が多く、費用の大半がここで発生します。 「OpenAI」を選んでいるときだけ働きます（Codex は自分で調べるため対象外）。
モデルは管理者が設定した既定を使います。うまく調べられなかった時は、 黙って他の方法に切り替えず、エラーとして知らせます。案内に従って設定を見直すか、 「使わない」に変更してください。
API キー（あなた専用）
管理者が許可している場合、現在選ばれているクラウド AI について 自分専用のキーを入力できます。使うモデルは管理者の「使えるモデル」設定に従います。

AWS Bedrock (Claude)

キーは管理者が設定します（このパソコン・利用者ごとの入力はできません）。
リージョン: 東京固定・モデルは推論プロファイル経由です。Bedrock コンソール（Playground）で発行した API キー（長期/短期）。未入力ならサーバ側 env（AWS_BEARER_TOKEN_BEDROCK など、または AWS 認証情報）を使用。本文テキストのみ送信。「利用可能なモデルを取得」は保存済みのキーでアカウントが 実際に使えるモデルを確認します（未保存の入力中キーは対象外・先に保存してください）。 Bedrock はアカウントごとに使えるモデルが異なるため、他の AI と違い一覧を管理者が 一律には用意できません（このためモデル選択のみここに残っています）。
「利用可能なモデルを取得」が失敗する場合（一覧取得には接続テストと別の AWS 権限が 必要なことがあります）でも、モデルIDが分かっていれば個別に検証して選択肢に追加できます （保存済みのキーで実際に1回だけ呼び出して確認・推測での追加はしません）。

ローカル LLM（Ollama）

管理者が許可した接続先から選びます。使うモデルは管理者の既定に従います。

Codex（チャット専用・grep して調べる）

Web 検索はチャット画面の調べ方ブロック（参照する行）で会話ごとに切り替えます。管理者が許可し、頭脳が Codex（OpenAI 直結）のときだけ表示されます。
OpenAI 本家への接続は API キー不要（CLI の `codex login` で認証）。接続先が Azure OpenAI 等の OpenAI 互換エンドポイントのときは、上の「OpenAI」欄の API キーを使います（保存前の入力中の値でも接続テストでは使えます）。モデルは管理者の「使えるモデル」の設定に従い、思考の深さは環境設定の既定（通常は `low`）に従います（どちらも個人設定にはありません）。ナレッジ抽出には非対応（チャット用）。接続テストは通常 CLI の有無とログイン状態を確認しますが、接続先が Azure OpenAI 等のときは実際に1回接続して確認します。
