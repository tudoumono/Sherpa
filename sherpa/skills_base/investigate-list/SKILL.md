# 資料一覧・件数調査レシピ

Sherpa 管理のベーススキル（自作）。型は「まずツールで当たりを付け→中身を確かめて→答える」（他の
investigate-* スキルと共通）。このスキルでは**件数・一覧は文書台帳（list_docs）が正**——本文を読んで
数え直さない。対象は**ファイル数・ファイル一覧・フォルダ構成**。本文中の項目（機能・帳票・処理・設定値
等）を「すべて」求められたときは台帳では答えられない——investigate-spec の全件手順に切り替える。

## 1. 最初に開くもの（当たりの付け方）

1. 対象フォルダの見当が付いていないときは `ripgrep_search(query=...)` か `es_search(query=...)` で
   キーワードを試し、ヒットした doc_id からフォルダの見当を付ける。フォルダ階層そのものを俯瞰したいときは
   `folder_tree(path_prefix=...)`（depth 既定3）を使う。
2. 見当が付いたら `list_docs(path_prefix="4期保守")` のように**フォルダで絞って**呼ぶ。フォルダ名・
   ファイル名の部分一致は `name_pattern` で当てる（grep で本文から探さない）。表記が揺れそうな語
   （例:「4期更改」がヒットしなければ「4期」）は短い部分語で試す。
3. `list_docs(path_prefix, name_pattern, doctype, state, limit, offset)` は `count`（絞り込み後の全件数・
   limit と無関係）と `docs`（rel_path 昇順・limit 件までの一覧）を返す。`doctype`／`state` でも絞れる。
   `truncated:true` なら `next_offset` から続きを取り、取得した総数を `count` と照合する。

候補フォルダが複数割れて曖昧なとき（例:「4期更改」と「4期保守」のどちらか判別できない）は、両方を
`list_docs` で数えてフォルダ別の内訳として答える（ask_user で確認してもよいが、内訳で答えられるなら
先にそちらを試す）。

## 2. 中身の確認（読取ツールが第一）

一覧・件数自体は `list_docs` の `docs`/`count` が正なので、本文を読んで数え直すことはしない。
ただし返ってきた `rel_path` の種別・分量をピンポイントで確かめたいときは、まず読取ツールを使う
（Python を書かない）。

- Excel（.xlsx）: `xlsx_sheets(doc_id=rel_path)` でシート名・行数・列数が返る（実在確認も兼ねる）。
- Word（.docx）: `docx_paragraphs(doc_id=rel_path, count=1)` で段落総数（`total`）と表の有無が分かる。
- PowerPoint（.pptx）: `pptx_slides(doc_id=rel_path, pages="1")` でスライド総数（`total`）が分かる。
- PDF: `pdf_pages(doc_id=rel_path, pages="1")` でページ総数（`total`）が分かる。
- テキスト・コード: `file_head(doc_id=rel_path, max_bytes=1024)` で先頭の中身と実在が分かる。

### 定型外のとき（読取ツールでは終わらない場合）

多数の `rel_path` の実在・サイズを一括で突き合わせるなど、読取ツールを1件ずつ呼ぶより Python で
まとめて確認したほうが速い場合だけ、原本を直接開く（読取専用・書き換えない）。

```python
from pathlib import Path

# rel_path は list_docs / folder_tree が返す「資料フォルダからの相対パス」。
# kb_root は資料フォルダの絶対パス（プロンプトに明示されている）。
p = Path(kb_root) / rel_path
if p.exists():
    print(p.name, p.suffix, p.stat().st_size, "bytes")
else:
    print(rel_path, "が見つからない（台帳と実体がずれている可能性）")
```

## 3. 完了条件と中断

- **ファイル一覧の依頼**: 対象フォルダが `list_docs` の `path_prefix` で一意に確定し、`truncated` が
  出なくなるまで `next_offset` で続けて取得したパス集合が `count` と一致したら終える。
- **件数だけの依頼**は、候補フォルダが2〜3個に絞れてそれぞれの件数が出せたら（内訳で答えられるなら）
  終えてよい——この打ち切りは件数質問に限り、一覧要求には適用しない。
- `ripgrep_search`/`es_search` を3回試しても手掛かりが増えないときは、範囲全体（`path_prefix` 省略）で
  `list_docs` を呼ぶ判断材料にしてよい（無理に絞り込みを続けない）。一覧要求はこれだけで終えず、
  `count` との照合まで行う。
- 秘匿名や範囲外のパスは `list_docs` 自体が返さない前提——返ってきた `docs` をそのまま数える。
- **フォルダ構成の依頼**は `folder_tree` の結果で答える。`folders_truncated:true` が付いたらフォルダ一覧は一部（`count`
  が総数・続きは取れない）＝その範囲を未確認として明示し「すべて」と書かない。
- **中断**（利用者停止・通信エラー・既存の反復／情報量予算への到達）のときは、確認済みの結果・
  未確認の範囲・中断理由を分けて書き、部分結果を「全件」「該当なし」と断定しない。

## 4. 回答の形

- 一覧を求められたら**該当する全件を各項目のパス付きで列挙する**（「など」で省略しない・件数と一致させる）。
- 件数を答えるときは、どのフォルダ（`path_prefix`）を数えたかを回答に明示する。曖昧なら候補フォルダ別の
  内訳で答える。
- 台帳の件数と、`ripgrep_search`/`es_search` のヒット件数は意味が違う（後者は本文中の一致数）——
  混同して答えない。
- 確定した事実（台帳の件数・一覧）と推定（フォルダ名から推測した分類等）は分けて書き、推定には
  「推定」と明示する。
- 本文の中に出典の一覧は書かない（一覧の依頼に対する各項目のパス列挙は答えそのものであり、ここで言う
  出典の一覧ではない）。回答の最後に『参照した資料:』の行を置き、実際に開いて根拠にした資料を1行1件、
  資料フォルダからの相対パスで列挙する。
