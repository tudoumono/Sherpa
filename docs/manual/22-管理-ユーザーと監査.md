# 22. 管理：ユーザーと監査

このページは管理者向けです。ユーザー管理と監査ログは `admin` ロールのユーザーだけが操作できます。

## ユーザー管理

「**ユーザー管理**」画面では、ユーザーの作成・無効化・役割変更・パスワード再設定ができます。

### ユーザーを追加する

1. ユーザー名（uid）を入力します。
2. 表示名を入力します。
3. 役割を選びます。
4. 初期パスワードを設定します。
5. **追加**を押します。

uid はログイン・会話所有・共有・個人 workspace・監査ログを結び付ける安定キーです。使用できる文字は英数字と `.` `_` `-` で、先頭は英数字です。

### 役割

| 役割 | できること |
|------|------------|
| `user` | チャット、会話履歴、会話共有、マイワークスペース、出典ダウンロード |
| `admin` | `user` の操作に加えて、資料フォルダの登録・取り込み、ユーザー管理、監査ログ閲覧 |

### 無効化とパスワード再設定

ユーザーは削除ではなく**無効化**します。無効化したユーザーの workspace は消しません。必要になれば再度有効化できます。

管理者は他ユーザーのパスワードを再設定できます。自分自身を無効化する操作は拒否されます。
初期パスワードと再設定パスワードは、8 文字以上の半角英数字・記号のみです。全角文字や空白は使えません。

## 初期 admin

認証は既定で有効です。初回起動時、`admin` ユーザーが存在しなければ自動作成されます。

| 項目 | 値 |
|------|----|
| uid | `admin` |
| 表示名 | `Administrator` |
| email | `admin@sherpa.local` |
| 初期パスワード | `Sherpa2026!`（`SHERPA_ADMIN_PASSWORD` を設定した場合はその値） |

1. アプリを起動します。
2. ユーザー名 `admin` と初期パスワードでログインします。
3. パスワード変更画面で新しいパスワードへ変更します。
4. ユーザー管理画面で通常ユーザーや追加管理者を作成します。

初期 `admin` には `must_change_password=true` が設定され、変更が完了するまで管理画面やチャットには進めません。本番運用では初期パスワードのまま使わないでください。

開発・検証で認証を無効化する場合だけ `SHERPA_AUTH_DISABLED=1` を使えます。通常運用では設定しません。

## 監査ログ

「**監査ログ**」画面では、誰が・いつ・何を・どの結果で実行したかを確認できます。

主な記録対象:

- ログイン、ログイン失敗、ログアウト
- ユーザー作成、無効化、役割変更、パスワード再設定
- 会話共有の作成、拒否、受領、取消
- 個人ファイルのアップロード、削除
- 出典ダウンロード
- 設定変更
- world 削除などの重要な管理操作

監査ログの閲覧自体も監査に残ります。画面では実行者、アクション、結果、重要度、期間で絞り込めます。

管理者は監査ログ画面から CSV / JSONL をエクスポートできます。現在のフィルタがエクスポートにも適用され、ファイル名は `sherpa-audit-YYYYMMDD-HHMMSS.csv` または `.jsonl` です。エクスポート操作も `admin.audit_exported` として監査ログに残ります。password / token / secret などの値は redaction されます。

## 改ざん検知

監査ログには hash-chain による改ざん検知があります。`GET /admin/audit/verify` で整合性を検証できます。

検出できるもの:

- 行の改ざん
- 並べ替え
- 末尾削除
- chain 開始後の偽行注入
- chain head の欠落

ただし anchor も同じ DB 内にあるため、DB 管理者権限を完全に信頼できない環境では、外部署名やエクスポートを別途検討します。
