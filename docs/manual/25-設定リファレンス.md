# 25. 設定リファレンス（全項目一覧）

「[13. 個人設定](13-個人設定.md)」と「[24. システム管理](24-システム管理.md)」の**設定項目を漏れなく一覧**にしたページです。
それぞれの画面に沿った詳しい説明・使い方の手順は元のページを参照してください。ここでは項目ごとに
**何をする設定か・どこに効くか・既定値・変えるとどうなるか（トレードオフ）**を短くまとめ、あわせて
保存先のキー名（`PUT /settings` または `PUT /admin/settings` に送るフィールド名）を添えます。
キー名は開発者・トラブル調査向けの手がかりで、通常の利用には不要です。

## この一覧の読み方

- **効く場所**: その設定を変えると、実際にどの機能の動きが変わるか。
- **既定値**: 一度も変更していない（画面で「既定に従っています」の状態の）ときの値。
- **変えると**: 値を変えたときのトレードオフを1行で（例: 広げると精度は上がるが費用も増える）。
- **キー**: 画面の裏で使われる設定名です。バックティックで表記します（例 `agent`）。

## 利用者設定（`settings.html`「個人設定」）

自分にだけ効きます。詳しい選択肢・入力例は「[13. 個人設定](13-個人設定.md)」を参照してください。

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| チャットに使う AI（頭脳） | チャットの回答を作る AI を選ぶ | `SHERPA_AGENT`（未指定なら自動選択） | 外部 AI に変えると回答品質は上がるが利用料・外部送信が発生する | `agent` |
| Codex の接続先（4構成） | Codex CLI が接続するモデル提供元（OpenAI／Ollama） | OpenAI | ローカル（Ollama）にすると無料・オフラインだが応答品質はモデル次第 | `codex_model_provider` |
| OpenAI API キー | 自分専用の OpenAI キー（管理者が個人キーを許可した場合のみ入力欄が表示） | 未設定（中央キーを使う） | 個人キーを使うと利用者ごとに課金元を分けられる | `openai_api_key` |
| Gemini API キー | 同上（Gemini） | 未設定 | 同上 | `gemini_api_key` |
| Bedrock API キー | 同上（AWS Bedrock） | 未設定 | 同上 | `bedrock_api_key` |
| Bedrock モデル | 使う Bedrock モデル（実在確認済みのものだけ選べる・個人設定に残る唯一のモデル選択） | JP 推論プロファイルの Claude Haiku 4.5 | 「利用可能なモデルを取得」または「検証して追加」で選択肢を増やせる | `bedrock_model` |
| ローカル AI（Ollama）の接続先 | チャット・下調べで使う Ollama の接続先（管理者が許可した一覧から選ぶ） | 管理者の既定接続先 | 社内の別ホストに向けると、そのホストの負荷・可用性に依存する | `ollama_url` |
| 下調べ（資料の検索）に使う AI | 「チャットに使う AI」が OpenAI のときだけ、資料を読む工程だけ安い AI に任せる | 使わない（自分で調べる） | 「OpenAI の低コストモデル」にすると費用を抑えられるが、下調べの精度がやや落ちることがある | `search_helper` |
| チャットの回答方針（システムプロンプト） | チャットの AI に与える追加の回答方針 | 空（モデル既定のまま） | 独自の方針を書くと、その方針に沿った回答になりやすい | `system_prompt` |

**個人設定に無いもの**: 使うモデル名（OpenAI/Gemini/Ollama/Codex）は「[24. システム管理](24-システム管理.md)」の
「使えるモデル」で管理者が決めます。Codex の推論の深さは環境設定の既定（通常 `low`）のみで、個人設定・チャットからの
上書きはありません。

**Web 検索の ON/OFF は個人設定にありません**: `settings.html`（個人設定）には Web 検索の入力欄はなく、
チャット画面の調べ方ブロック（「参照する」行・頭脳が Codex（OpenAI 直結）かつ管理者が許可している
ときだけ表示）で会話ごとに切り替えます。新しい会話を始めると常に OFF から始まり、この選択は個人設定
として保存されません（保存される設定値は「[24. システム管理](24-システム管理.md)」の
「Web 検索を許可する」＝`web_search_allowed` だけです）。個人設定のスキーマには過去の名残で
`codex_web_search` という列がありますが、**実行時には読まれません**（実際に使われる値は、その会話の
チャット依頼に含まれる Web 検索の希望だけです）。

## 管理者設定（`admin-settings.html`「システム管理」）

全ユーザーに効きます。`admin` ロールが必要です。詳しい説明・操作手順は
「[24. システム管理](24-システム管理.md)」を参照してください。タブの並び順でまとめます。

### タブ: プロバイダ＋接続先

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| クラウド AI の選択 | OpenAI／Gemini／AWS Bedrock から同時に1つを選ぶ（排他） | OpenAI | 選び直すとチャット・整形など全機能がそのプロバイダに切り替わる | `cloud_provider` |
| 各プロバイダの中央 API キー | 全員が共用する API キー | 未設定 | 未設定のままだとそのプロバイダは使えない | `openai_api_key` / `gemini_api_key` / `bedrock_api_key` |
| 利用者ごとの個人キーを許可する | ON で利用者が自分の API キーを個人設定に保存・優先利用できる | OFF | OFF にして保存すると、既に保存済みの利用者の個人キーは全削除される | `personal_api_keys_allowed` |
| Web 検索を許可する（Codex のみ） | ON で Codex（OpenAI 直結）利用者がチャットごとに Web 検索を選べる | OFF | ON にすると検索語が OpenAI 側の検索機能へ渡る（社内資料そのものは送らない） | `web_search_allowed` |
| ローカル AI（Ollama）の既定接続先 | クラウドの選択と無関係に常に使える Ollama の既定接続先 | `http://localhost:11434` | 社内共有の Ollama サーバへ向けると、複数人で1台を共用できる | `ollama_url` |
| 利用者が選べる接続先（Ollama 許可リスト） | 個人設定で選べる Ollama 接続先の一覧（`host:port`） | 空（localhost のみ） | 追加すると、その接続先も個人設定の選択肢に出る | `ollama_allowlist` |
| Webhook の許可先 | 外部連携キーの Webhook 通知が送れる宛先の一覧（`host:port`） | 空（localhost のみ） | 追加しない宛先は、キー発行時に Webhook URL として指定できない | `webhook_allowlist` |
| OpenAI の接続先（本家／Azure／その他互換） | OpenAI 互換 API の接続先種別・URL・認証ヘッダ・API バージョン | OpenAI 本家 | Azure 等へ切り替えると、既存の検索索引（埋め込み）と食い違い再取り込みが要ることがある | `openai_endpoint_kind` / `openai_base_url` / `openai_auth_header` / `openai_api_version` |
| 探索の反復回数（標準） | エージェント検索（grep 反復）の反復ターン数上限の基準値 | 12（`SHERPA_AGENTIC_MAX_TURNS`。出荷テンプレは24） | 増やすと調査は粘るが時間・費用が増える（範囲 1〜200） | `depth_base_max_turns` |
| 資料検索のヒット件数上限（標準） | grep／全文検索1回あたりのヒット数上限の基準値 | 30（`SHERPA_GREP_MAX_HITS`。出荷テンプレは45） | 広げると見落としは減るが読む量（費用）が増える（範囲 1〜1000） | `depth_base_grep_max_hits` |
| 内容の質問のヒット件数上限（標準） | 仕様問い合わせ（QA レンズ）のヒット件数上限の基準値 | 20（コード組み込み・env なし） | 同上（範囲 1〜1000） | `depth_base_qa_max_hits` |
| 1回に読み取る前後の行数（標準） | 精読（read_around）で1回に読む窓の行数の基準値 | 40（`SHERPA_READ_WINDOW`。出荷テンプレは60） | 広げると文脈は掴みやすいが1回の読み取り量（費用）が増える（範囲 10〜400） | `depth_base_read_window` |
| 影響を調べる深さ（標準） | 影響分析でグラフをたどる深さの基準値 | 8（`SHERPA_IMPACT_MAX_DEPTH`。出荷テンプレは10） | 深くすると波及範囲を広く拾えるが、密なグラフでは応答が遅くなる（範囲 1〜64） | `depth_base_impact_depth` |
| 原因を調べる近傍の深さ（標準） | トラブルシュートで近傍をたどる深さの基準値 | 3（`SHERPA_TROUBLESHOOT_GRAPH_DEPTH`。出荷テンプレは4） | 同上の考え方（範囲 1〜16） | `depth_base_troubleshoot_depth` |
| Codex の推論レベル（標準） | Codex の思考の深さの基準値 | 環境設定の既定（通常 `low`） | 上げると回答の粘りは増すが時間・費用も増える | `depth_base_codex_reasoning` |
| チャットの質問例（クイック入力） | チャット画面のウェルカム表示にある、クリックで入力欄に読み込める質問例チップの文言 | 表示する・組み込みの4例 | オフにするとブロック自体が非表示になる。文言を差し替えると導入先固有の質問例を示せる（1〜8件・各200文字まで） | `chat_examples`（内訳: `enabled`・`items`） |

「調べる深さ」（チャットの調べ方ブロックにある**標準／深く／最大**）は、上の基準値に固定の倍率
（反復回数は ×1／×2／×3、ヒット件数・読み取り窓は ×1／×1.5／×2、影響・近傍の深さは +0／+2／+4、
Codex 推論レベルは 変更なし／`high`／`xhigh`）をかけて動きます。倍率そのものはこの画面では編集できません
（編集できるのは「標準」が指す基準値だけです）。

### タブ: 使えるモデル

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| 使えるモデル一覧・既定（用途×プロバイダ） | チャット・整形・意味理解・下調べ・埋め込み等、用途ごとに選べるモデル名と既定を決める | 組み込みの一覧（例: OpenAI チャット既定 `gpt-5.5`・埋め込み既定 `text-embedding-3-small`） | 既定を変えると次回以降すぐにその値が使われる（利用者側の切替操作は不要） | `model_catalog` |

Bedrock だけは対象外です（実在確認済みのモデルを利用者本人が「個人設定」の「モデルIDを直接追加」等で選ぶ、別の仕組みを使います）。

### タブ: 取り込み

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| 取り込みアーム（読み取り方式） | Office 直接読み取り／PDF 文字抽出／視覚読み取りのどれを有効にするか | `ooxml`,`pdf_text`（`SHERPA_ARMS` が既定のフォールバック） | 「視覚読み取り」を足すと、文字が少ない PDF・スキャン画像も拾えるが AI 呼び出しが増える | `arms_enabled` |
| 旧形式（.doc/.xls/.ppt）の変換 | 変換バックエンド（使わない／LibreOffice／Office 連携） | `none`（`SHERPA_LEGACY_BACKEND` が既定のフォールバック） | 変換方式を選ぶと古い形式のファイルも取り込み対象になる | `legacy_backend` |
| 視覚読み取りの AI（VLM） | 「視覚読み取り」アームが使う AI（`provider`／`model`／クラウド許可） | provider=`ollama`・model=`qwen2.5vl`・cloud_allowed=false | クラウド（OpenAI）を許可すると画像が外部へ送信される | `vlm`（内訳: `provider`・`model`・`cloud_allowed`） |
| AI で検索用の文書を読みやすく整形する | 取り込んだ資料を AI で検索用に自動整形するか | `off` | ON にすると取り込み後に自動整形が走り利用料が発生する（実測では文体の整形にとどまり情報の追加・復元はない） | `rag_llm_render` |
| 検索結果1件あたりの上限（KB） | AI が資料を検索するとき、検索結果1件に使う情報量の上限 | 256KB（コード既定・精度優先） | 広げると精度は上がるが AI への送信量（利用料）が増える（範囲 1〜8192KB） | `agentic_budget_per_result` |
| 1回の検索全体の上限（KB） | 1回の検索（1 run）で読み込む情報量の合計上限 | 4096KB（コード既定・精度優先） | 到達すると、そこまでに調べた内容だけで回答をまとめる（範囲 4〜65536KB） | `agentic_budget_total` |
| モデルの窓の登録 | プロバイダAPIから自動で分からないモデルの窓（トークン数）を手動登録する表 | 空（プロバイダAPI／組み込みの一覧から自動解決） | 登録した窓を超えないところまで、上の2つの予算が自動で縮む（増えることはない） | `model_context_windows` |

「検索1回あたりの情報量（予算）」（`agentic_budget_per_result`／`agentic_budget_total`／`model_context_windows`）は、
エージェント検索（grep 反復で調べる方式）専用の費用の安全弁です。以前は環境変数で調整していましたが、
現在はこの画面（管理画面）だけが唯一の設定場所です（env 経由の指定は撤去済み）。

## プロバイダ別セットアップ手順

チャット・検索用文書の整形・埋め込み（検索索引）に使う4つの AI 接続先の、設定する順番とつまずきやすい点です。
いずれも「[24. システム管理](24-システム管理.md)」の「プロバイダ＋接続先」タブで設定します。

### OpenAI 本家

1. 「クラウド AI の選択」で **OpenAI** を選ぶ。
2. **API キー**（`sk-...`）を入力し、「接続テスト」で疎通を確認する（最小リクエストを1回だけ送信・保存はしない）。
3. 「使えるモデル」タブで、チャット・埋め込み等の既定モデルを確認する（組み込み既定のままでよければ変更不要）。
4. 資料フォルダを取り込むと、埋め込み（検索索引の作成）が自動で走る。**専用の疎通確認ボタンはなく**、
   実際に取り込みを1回動かして確認する運用です。失敗した場合は資料フォルダの取り込み状況
   （「[20. 資料の取り込み](20-管理-取り込み.md)」）にエラーが表示されます。

つまずきやすい点: 「利用者ごとの個人キーを許可する」が OFF（既定）のままだと、利用者の個人設定に
API キー入力欄自体が出ません（意図した挙動です）。クラウド AI を切り替えた直後は、以前の索引と
埋め込みモデルが食い違うことがあるため、資料フォルダの再取り込みが必要になる場合があります。

### Azure OpenAI

Azure OpenAI（またはその他の OpenAI 互換エンドポイント）への切り替え手順・接続先 URL の書式・
API バージョンの要否・つまずきやすい点（デプロイ名・認証ヘッダ形式・埋め込み次元の固定など）は分量が多いため、
「[24. システム管理](24-システム管理.md)」の「接続先を Azure OpenAI にする」に一本化しています。
`make azure-smoke` による導入前の疎通確認（実 API を叩かない `--dry-run` を含む）もそちらを参照してください。

### Gemini（Google）

1. 「クラウド AI の選択」で **Gemini（Google）** を選ぶ。
2. **API キー**（`AIza...`）を [Google AI Studio](https://aistudio.google.com/apikey) で取得して入力し、
   「接続テスト」で疎通を確認する。
3. 「使えるモデル」タブで、チャット・埋め込み（`gemini-embedding-001`・次元は 1536 固定）の既定を確認する。
4. OpenAI と同様、埋め込みの疎通は専用ボタンではなく実際の取り込みで確認します。

つまずきやすい点: Gemini はローカル AI（Ollama）と違って外部送信が発生します（本文テキストのみ・ファイルは送りません）。
Bedrock と異なりモデル選択は個人設定に無く、「使えるモデル」タブでのみ管理します。

### ローカル LLM（Ollama）

Ollama は「クラウド AI の選択」（排他選択）の対象外で、クラウドの選択に関わらず常に併用できます。

1. Ollama をこのパソコン（または社内ネットワークのサーバー）で起動する（`ollama serve`）。
2. 使うモデルを事前に取得する（例: チャット用 `ollama pull qwen2.5`・埋め込み用 `ollama pull nomic-embed-text`
   （埋め込みの次元は 768 固定）・視覚読み取り用 `ollama pull qwen2.5vl`）。
3. 「ローカル AI（Ollama）の既定接続先」を設定する（既定は `http://localhost:11434`）。自分のパソコンだけで
   使う場合はそのままで構いません。
4. 複数人で社内共有の Ollama サーバーを使う場合は、「利用者が選べる接続先（許可リスト）」に
   `host:port` を追加する（追加していない接続先は個人設定から選べません）。
5. 個人設定（またはシステム管理の「実行構成」）で **ローカル（Ollama）** を頭脳に選び、「接続テスト」で疎通を確認する。

つまずきやすい点: モデルを取得（`pull`）し忘れると、接続はできても実行時にモデル未検出のエラーになります。
視覚読み取りで社内ネットワークの Ollama を使う場合は、接続先を **IP アドレス**で指定する必要があります
（ドメイン名を使うには、別途「クラウド AI（OpenAI）の利用を許可する」も必要です・「[24. システム管理](24-システム管理.md)」参照）。
