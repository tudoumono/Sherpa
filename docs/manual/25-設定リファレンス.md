# 25. 設定リファレンス（全項目一覧）

「[13. 個人設定](13-個人設定.md)」と「[24. システム管理](24-システム管理.md)」の**設定項目を漏れなく一覧**にしたページです。
それぞれの画面に沿った詳しい説明・使い方の手順は元のページを参照してください。ここでは項目ごとに
**何をする設定か・どこに効くか・既定値・変えるとどうなるか（トレードオフ）**を短くまとめ、あわせて
保存先のキー名（`PUT /settings` または `PUT /admin/settings` に送るフィールド名）を添えます。
キー名は開発者・トラブル調査向けの手がかりで、通常の利用には不要です。

## この一覧の読み方

- **効く場所**: その設定を変えると、実際にどの機能の動きが変わるか。
- **既定値**: 一度も変更していない（画面で「既定に従っています」の状態の）ときの値。
- **変えると**: 値を変えたときのトレードオフを1行で（例: 広げると精度は上がるが費用も増える）。
- **キー**: 画面の裏で使われる設定名です。バックティックで表記します（例 `agent`）。

## 利用者設定（`settings.html`「個人設定」）

自分にだけ効きます。詳しい選択肢・入力例は「[13. 個人設定](13-個人設定.md)」を参照してください。

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| チャットに使う AI（頭脳） | チャットの回答の作り方を選ぶ（「Codex 調査（OpenAI）」「Codex 調査（Ollama）」「簡易（検索して答える）」の3つ）。以前の「OpenAI」「ローカル（Ollama）」直結の保存値は簡易として扱い、「AIなし」「Gemini」「AWS Bedrock」の保存値は選び直しを案内して止まる | 自動選択（Codex CLI と使える認証があれば Codex 調査、なければ簡易） | 簡易は手早いが調べる範囲が浅い。網羅性・確証が要る質問は Codex 調査 | `agent` |
| Codex の接続先（OpenAI／Ollama） | Codex CLI が接続するモデル提供元 | OpenAI | ローカル（Ollama）にすると無料・オフラインだが応答品質はモデル次第 | `codex_model_provider` |
| OpenAI API キー | 自分専用の OpenAI キー（管理者が個人キーを許可した場合のみ入力欄が表示）。Codex 調査の接続先が Azure OpenAI など OpenAI 以外のときに使われる。簡易は中央のキーだけを使う | 未設定（中央キーを使う） | 個人キーを使うと利用者ごとに課金元を分けられる | `openai_api_key` |
| ローカル AI（Ollama）の接続先 | 「Codex 調査（Ollama）」で使う Ollama の接続先（管理者が許可した一覧から選ぶ）。簡易は使わない | 管理者の既定接続先 | 社内の別ホストに向けると、そのホストの負荷・可用性に依存する | `ollama_url` |

**個人設定に無いもの**: 使うモデル名（OpenAI/Ollama/Codex）は「[24. システム管理](24-システム管理.md)」の
「使えるモデル」で管理者が決めます。Codex の推論の深さは管理者の基準値（未設定のときは既定の `medium`。調べる深さがクイックのときだけ 1 段下がります）で決まり、個人設定・チャットからの
上書きはありません。**回答方針（システムプロンプト）はアプリで固定**で、個人設定にも管理画面にも書き換える欄はありません。
下調べに使う AI の選択欄もありません（Codex 調査の下調べ役のモデルは管理者が決めます）。簡易が使う AI も個人設定にはなく、
管理者の「簡易回答に使う AI」で決まります（下の「タブ: 外部連携」）。

**Web 検索の ON/OFF は個人設定にありません**: `settings.html`（個人設定）には Web 検索の入力欄はなく、
チャット画面のやりたいことブロック（「参照する」行・頭脳が「Codex 調査（OpenAI）」かつ管理者が許可している
ときだけ表示。簡易では表示されません）で会話ごとに切り替えます。新しい会話を始めると常に OFF から始まり、この選択は個人設定
として保存されません（保存される設定値は「[24. システム管理](24-システム管理.md)」の
「Web 検索を許可する」＝`web_search_allowed` だけです）。個人設定には Web 検索の希望を保存する列も
ありません（実際に使われる値は、その会話のチャット依頼に含まれる Web 検索の希望だけです）。

### タブ: 調査・回答

接続先と分けて、設定が効く経路ごとに表示します。既存の保存値は引き継がれます。

#### 見直し（査読）の回数

「調べる深さ」が決める、下調べ役の一次判断を見直す回数です。Codex 調査で働きます（簡易は見直しを行いません）。

| 深さ | 見直しの回数 |
|---|---|
| クイック | 0回（見直しはせず、一次判断の確認1回だけで答えます） |
| 標準 | 2回 |
| 深く | 4回 |
| 最大 | 下の「最大の見直しの回数」の設定値まで |

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| 最大の見直しの回数 | 「調べる深さ」が最大のときに使う見直し回数の上限 | 7（範囲 1〜32） | **標準・深くの回数も、この値より多くはなりません**（下げると「深く」の4回もこの値までに縮みます）。十分に調べられたときは、設定した回数に達する前に見直しを終えます | `max_review_rounds` |

#### Codex の調査

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| Codex の調べ方 | 標準（Sherpa の検索ツールと調査台帳を使う）か、素の Codex（Codex が自分で資料を読む・試験用）かを選ぶ | 標準 | 素の Codex では「調べる深さ」は Codex の調べ方（見直しの回数・推論の強さ）には効きません。影響調査で一覧を作るときのたどる深さにだけ効きます。 | `codex_mode` |
| 下調べ役のモデル名 | Codex が観点ごとの下調べ（worker）に使うモデルの名前 | 空（Azure／ローカル（Ollama）接続なら本体と同じモデル名・それ以外は組み込みの確認済みモデル） | 空以外を指定すると、その名前が Codex 自身のモデルカタログに実在する必要がある（実在しないモデル名だと下調べの起動に失敗する）。この値は全構成に共通で適用されるため、ローカル（Ollama）構成の利用者がいる環境では Ollama 側にも存在するモデル名にする（OpenAI 向けの名前を入れると Ollama 構成の下調べが毎回失敗する）。Azure／ローカル（Ollama）では未設定時に本体と同じデプロイ名／モデル名・接続先設定を下調べ役にも使うが実機未検証のため、**初回は spawn の成功と接続先ログを確認すること**（独自エンドポイント（custom）は未設定のままだと下調べ機能自体を無効化する） | `codex_worker_model` |
| Codex の会話セッションを保存する日数 | 会話ごとの Codex resume セッション（`workspace/.codex-sessions/`）を何日で自動削除するか | 30 | 0 で無制限。短くすると古い会話は resume できなくなる（新規セッションとして続く）。**アップグレード後、未設定は 30 日として扱われ、30 日以上触っていない会話の Codex セッションは最初の掃除で削除される。従来どおり残すなら先に 0 を明示保存する** | `codex_session_retention_days` |
| Codex の推論レベル（標準・作成以外） | 通常の調査の推論レベル。「作成」の標準は専用の環境設定を使用 | `medium` | 上げると推論に使う時間・費用が増える場合がある。**「調べる深さ」がクイックのときだけ、ここで決めた値より自動で1段下がります**（クイックは「速いが浅い」設定のため。それ以外の深さでは変わりません。素の Codex では下がりません。`low` 以下はそれ以上下がりません） | `depth_base_codex_reasoning` |

#### 取り込み・検索の共通設定

資料の取り込み（埋め込みの同時送信数）と、Codex が検索ツールから受け取る結果1件あたりの情報量の上限です。

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| 埋め込みの同時送信数 | 資料の取り込み時に、埋め込み API へ同時に送るリクエスト数 | 4 | 範囲1〜16。保存した値は次に開始する取り込みから反映されます（実行中の取り込みは開始時の値のまま）。大きくすると取り込みが速くなるが、プロバイダ側の同時実行/レート制限に早く当たることがある | `embed_parallel` |


#### Codex の調査で受け取る情報量

「前後の行数」が読む範囲を決め、この設定が結果のデータ量を制限します。行数の範囲内でも情報量の上限で切り詰める場合があります。
**この上限は Codex が Sherpa の検索ツールから受け取る結果1件に働きます**（Codex には別に固定の上限＝1件64KBもあり、
どちらか小さい方が使われます）。簡易は固定の上限（AI への往復3回・1往復あたり道具4回）で動き、設定はありません。

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| ツール結果1件あたりの上限（KB） | AI が資料を検索するとき、検索結果1件に使う情報量の上限 | 256KB（コード既定・精度優先） | 広げると精度は上がるが AI への送信量（利用料）が増える（範囲 1〜8192KB） | `agentic_budget_per_result` |

「Codex の調査で受け取る情報量」（`agentic_budget_per_result`）は、以前は環境変数で調整していましたが、
現在はこの画面（管理画面）だけが唯一の設定場所です（env 経由の指定は撤去済み）。


#### 共通の資料検索・関係探索

資料を探す件数・読む行数・たどる段数の基準値です。実際に効くのは Codex 調査です（簡易には効きません）。

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| 資料検索のヒット件数上限（標準） | grep／全文検索1回あたりのヒット数上限の基準値（Codex に渡す検索ツールに効く） | 45 | 広げると見落としは減るが読む量（費用）が増える（範囲 1〜1000） | `depth_base_grep_max_hits` |
| 1回に読み取る前後の行数（標準） | 精読（read_around）で1回に読む窓の行数の基準値（Codex に渡す検索ツールに効く） | 60 | 広げると文脈は掴みやすいが1回の読み取り量（費用）が増える（範囲 10〜400） | `depth_base_read_window` |
| 内容の質問のヒット件数上限（標準） | 仕様問い合わせ（QA・やりたいこと）のヒット件数上限の基準値 | 20（コード組み込み・env なし） | 同上（範囲 1〜1000） | `depth_base_qa_max_hits` |
| 影響分析でたどる段数（標準） | 「ここを変更すると、どこに影響するか」。変更対象から登録された関係をたどり、影響先の候補を探す | 10 | 1段は直接つながる箇所、2段はその先まで。増やすと探索範囲が広がり、処理時間も増えることがある（範囲 1〜64） | `depth_base_impact_depth` |
| 原因調査でたどる段数（標準） | 「この問題は、何が原因か」。症状に関連する箇所から周囲の関係をたどり、原因候補を探す | 4 | 段数の数え方は影響分析と同じ。増やすと原因候補を探す範囲が広がる（範囲 1〜16） | `depth_base_troubleshoot_depth` |

**二つの段数は、揃える必要はありません。** 影響分析は関係の種類と方向を絞りますが、原因調査は向きを限定せず周囲を探すため、同じ段数でも探索範囲が広がりやすくなります。範囲を広げたい調査の項目だけ調整してください。
原因調査では関連資料も検索し、候補と根拠をその後の調査に使います。この候補収集だけで原因を確定しません。

「調べる深さ」（チャットのやりたいことブロックにある**クイック／標準／深く／最大**）は、上の基準値に
固定の倍率をかけて動きます。倍率そのものはこの画面では編集できません（編集できるのは「標準」が指す
基準値だけです）。簡易を選んでいるときは「調べる深さ」の行自体が隠れ、効きません。

| 深さ | ヒット件数・読み取り窓 | 影響・近傍の深さ | 見直しの回数 | Codex 推論レベル |
|---|---|---|---|---|
| クイック | ×0.5（最低1は確保） | +0 | 0回 | 上の基準値より**自動で1段下げる**（クイックだけの例外） |
| 標準 | ×1 | +0 | 2回 | 変更なし |
| 深く | ×1.5 | +2 | 4回 | 変更なし |
| 最大 | ×2 | +4 | 「最大の見直しの回数」まで | 変更なし |

**クイックは「速いが浅い」設定です**（探索量を半分に絞り、見直しをせず、Codex の推論レベルも1段下げて、素早く
答えを返すことを優先します）。

### タブ: 使えるモデル

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| 使えるモデル一覧・既定（用途×プロバイダ） | 接続テスト・意図判定・簡易・Codex・整形・埋め込み等、用途ごとに選べるモデル名と既定を決める | 組み込みの一覧（例: OpenAI チャット既定 `gpt-5.5`・埋め込み既定 `text-embedding-3-small`） | 既定を変えると次回以降すぐにその値が使われる（利用者側の切替操作は不要） | `model_catalog` |

### タブ: 取り込み

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| 取り込みアーム（読み取り方式） | Office 直接読み取り／PDF 文字抽出／視覚読み取りのどれを有効にするか | `ooxml`,`pdf_text` | 「視覚読み取り」を足すと、文字が少ない PDF・スキャン画像も拾えるが AI 呼び出しが増える | `arms_enabled` |
| 旧形式（.doc/.xls/.ppt）の変換 | 変換バックエンド（使わない／LibreOffice／Office 連携） | `none` | 変換方式を選ぶと古い形式のファイルも取り込み対象になる | `legacy_backend` |
| 視覚読み取りの AI（VLM） | 「視覚読み取り」アームが使う AI（`provider`／`model`／クラウド許可） | provider=`ollama`・model=`qwen2.5vl`・cloud_allowed=false | クラウド（OpenAI）を許可すると画像が外部へ送信される | `vlm`（内訳: `provider`・`model`・`cloud_allowed`） |
| AI で検索用の文書を読みやすく整形する | 取り込んだ資料を AI で検索用に自動整形するか | `off` | ON にすると取り込み後に自動整形が走り利用料が発生する（実測では文体の整形にとどまり情報の追加・復元はない） | `rag_llm_render` |

### タブ: 外部連携（API キー）

| 項目 | 何をする設定か | 既定値 | 変えると | キー |
|------|---------------|--------|----------|------|
| 利用者のキー発行を許可する | ON で利用者が個人設定から自分の API キーを発行・管理できる | OFF | OFF に戻すと、利用者が発行したキーはすべて自動的に失効する | `user_api_keys_allowed` |
| 利用者キーの1日あたりの呼び出し上限 | 利用者が自己発行するキーの既定値／上限 | 100（コード組み込みのフォールバック） | 変更は新規発行から適用（発行済みキーの上限は変わらない） | `user_api_keys_daily_quota_default` |
| 簡易回答に使う AI（チャットの簡易・外部 API 共通） | チャットで「簡易」を選んだときと、`POST /ext/v1/answer` で答えるときに使う AI（利用者・呼び出し側は指定できない） | ローカル（Ollama） | クラウド（OpenAI）を選ぶには、あらかじめ OpenAI のキー設定が必要 | `research_default_provider` |

## プロバイダ別セットアップ手順

チャット・検索用文書の整形・埋め込み（検索索引）に使う3つの AI 接続先の、設定する順番とつまずきやすい点です。
いずれも「[24. システム管理](24-システム管理.md)」の「プロバイダ＋接続先」タブで設定します。

### OpenAI 本家

1. クラウド AI は **OpenAI**（Azure OpenAI を含む）の1つだけなので、選ぶ操作は要りません（過去に Gemini／AWS Bedrock を保存していて画面に警告が出ている場合だけ、OpenAI を選び直して保存する）。
2. **API キー**（`sk-...`）を入力し、「接続テスト」で疎通を確認する（最小リクエストを1回だけ送信・保存はしない）。
3. 「使えるモデル」タブで、チャット・埋め込み等の既定モデルを確認する（組み込み既定のままでよければ変更不要）。
4. 資料フォルダを取り込むと、埋め込み（検索索引の作成）が自動で走る。**専用の疎通確認ボタンはなく**、
   実際に取り込みを1回動かして確認する運用です。失敗した場合は資料フォルダの取り込み状況
   （「[20. 資料の取り込み](20-管理-取り込み.md)」）にエラーが表示されます。

つまずきやすい点: 「利用者ごとの個人キーを許可する」が OFF（既定）のままだと、利用者の個人設定に
API キー入力欄自体が出ません（意図した挙動です）。クラウド AI を切り替えた直後は、以前の索引と
埋め込みモデルが食い違うことがあるため、資料フォルダの再取り込みが必要になる場合があります。

### Azure OpenAI

Azure OpenAI（またはその他の OpenAI 互換エンドポイント）への切り替え手順・接続先 URL の書式・
API バージョンの要否・つまずきやすい点（デプロイ名・認証ヘッダ形式・埋め込み次元の固定など）は分量が多いため、
「[24. システム管理](24-システム管理.md)」の「接続先を Azure OpenAI にする」に一本化しています。
`make azure-smoke` による導入前の疎通確認（実 API を叩かない `--dry-run` を含む）もそちらを参照してください。

### ローカル LLM（Ollama）

Ollama はクラウド AI の選択とは別に、いつでも併用できます。

1. Ollama をこのパソコン（または社内ネットワークのサーバー）で起動する（`ollama serve`）。
2. 使うモデルを事前に取得する（例: チャット用 `ollama pull qwen2.5`・埋め込み用 `ollama pull nomic-embed-text`
   （埋め込みの次元は 768 固定）・視覚読み取り用 `ollama pull qwen2.5vl`）。
3. 「ローカル AI（Ollama）の既定接続先」を設定する（既定は `http://localhost:11434`）。自分のパソコンだけで
   使う場合はそのままで構いません。
4. 複数人で社内共有の Ollama サーバーを使う場合は、「利用者が選べる接続先（許可リスト）」に
   `host:port` を追加する（追加していない接続先は個人設定から選べません）。
5. 個人設定で「**Codex 調査（Ollama）**」を頭脳に選び、「接続テスト」で疎通を確認する。簡易でローカル AI を使うときは、「外部連携」タブの「簡易回答に使う AI」を **ローカル（Ollama）** にする（既定）。

つまずきやすい点: モデルを取得（`pull`）し忘れると、接続はできても実行時にモデル未検出のエラーになります。
視覚読み取りで社内ネットワークの Ollama を使う場合は、接続先を **IP アドレス**で指定する必要があります
（ドメイン名を使うには、別途「クラウド AI（OpenAI）の利用を許可する」も必要です・「[24. システム管理](24-システム管理.md)」参照）。

#### Ollama の接続先はどこで決まるか

接続先の指定は 2 か所に分かれています。片方だけ直して食い違わないよう、次の表で確かめてください。視覚読み取り（VLM）も同じ接続先（管理画面の既定接続先・許可リスト）を使います。

| 指定 | 効き方 | 変えるには |
|---|---|---|
| 環境設定の `OLLAMA_URL` | **初回起動時に 1 回だけ**、管理画面の「ローカル AI（Ollama）の既定接続先」へ取り込まれる。2 回目以降は書き換えても反映されない | 管理画面「プロバイダ＋接続先」 |
| 管理画面の「ローカル AI（Ollama）の既定接続先」（`ollama_url`） | 簡易（Ollama を使うとき）・Codex 調査（Ollama）が実際に使う接続先。localhost 以外は「利用者が選べる接続先（許可リスト）」に `host:port` が必要 | 管理画面（個人設定で許可リストの中から選び直すこともできる） |

Ollama 自身の環境変数 `OLLAMA_HOST` は Sherpa の接続先には効きません（Codex（Ollama）も、Sherpa が
管理画面の接続先を Codex へ渡します）。

#### Codex（Ollama）に使うモデル名

Codex（Ollama）では、「使えるモデル」の **Codex の列・用途「Codex」の行** に **Ollama に取得済みのモデル名**
（例 `gpt-oss:20b`・`qwen3:32b`）を登録して既定に選びます（「Ollama」の列は簡易・埋め込みなど Codex を使わない用途のモデル用）。
既定の OpenAI 向けの名前（`gpt-5.5` など）のままにしたり、Codex が知っている OpenAI のモデル名を入れたりすると、
Codex が Ollama の対応していない入力を送って毎回失敗します。個人設定の「接続テスト」は、そのモデルが Ollama に
取得済みかまで確かめます。
