# 30. しくみ（アーキテクチャ）

実装の全体像を、現在の動作のままに説明します。深掘りの一次資料は各所のリンク先（[03-鏡モデル.md](../03-鏡モデル.md) など）。

## 1. ディレクトリの鏡（取り込みモデル）

正典は [03-鏡モデル.md](../03-鏡モデル.md)。

- **登録ディレクトリ＝1つの世界**（`world`）。**1グラフ（Neo4j）＋1全文索引（Elasticsearch）**を持ちます。
- **範囲＝フォルダのフィルタ**。どの階層でも、その部分木を1つの範囲として検索・分析できます。グラフも全文索引も同じフィルタが効きます。
- **同一性＝パス**。複製は別ノード。リンク（COPY/CALL 等）は同世代（トップフォルダ）内の最近傍で結び、世代を跨ぎません。
- **置いた構造をそのまま映す**: 更新＝置換／削除＝消える（反映は自動監視でなく、取り込み実行時＝登録／`/worlds/{id}/refresh`／`/ingest/rerun`／任意ポーリング `SHERPA_POLL_SECONDS>0`）。「版」という固定概念は持たず、世代はトップフォルダで表します。

原本は登録フォルダ（読み取り専用）に置かれたまま。派生物は役割ごとに3層へ分けて `data/derived/{world}/` に作ります: **`md/`**＝人が読む写し（**決定的 Markdown**・画面表示や原本DL の根拠）、**`rag/`**＝RAG 正本（`{rel}.rag.md`＋証跡）、**`ir/`**＝中間表現（再生成可能・検索には出しません）。**grep・ES（全文/ベクトル）・グラフ（資料文書とコードの言及エッジ）はいずれも `rag/` の `rag.md` を読みます**（rag.md が検索用表現の唯一の正本）。グラフ側は AI で意味を読み取るのではなく、コードの定義名を辞書として資料本文と機械的に突き合わせるだけです（決定的・網羅的）。**出典（doc_id）は常に原本のパス**を指すので、ダウンロードは原本バイナリを返します。

## 2. 検索・調べ方（3種類）

AI エージェントは依頼に応じて道具を使い分けます。**トラブルシュート・仕様問い合わせ**では AI が自分で道具を選んで反復し、**影響範囲分析**では先に決定的なグラフ探索を実行して事実を集めます。

| 調べ方 | 実体 | 強み |
|--------|------|------|
| **grep** | 登録フォルダ（ソース原文はそのまま／Office は派生 RAG 正本 rag.md）の行単位検索 | 完全一致・固有名詞・関数名 |
| **ES（全文）** | Elasticsearch・kuromoji BM25（＋任意でベクトル） | 表記ゆれ・自然文（言い換えはベクトル有効時のみ） |
| **グラフ（影響）** | Neo4j の近傍探索 | つながり・経路・影響範囲 |

- **影響範囲分析**はグラフ駆動（成果物がグラフそのもの＝逆向き探索で「何に波及するか」を経路つきで返す）。
- **トラブルシュート／仕様問い合わせ**は **agentic**（AI が grep / ES / グラフ近傍を自分で引いて答える）。
- 出典の実在は毎回チェックし、現在の世界に無い doc は引用元に出しません。

## 3. AI エージェント（頭脳）

回答に使う AI はユーザごとに選べます。

- **OpenAI / Gemini / Ollama**: function-calling でツール（grep/ES/グラフ近傍）を呼びながら調べます（**トラブルシュート・仕様問い合わせ**のとき）。**影響範囲分析は先に決定的なグラフ探索**を実行し、その結果を AI が文章化します。
- **Codex**: OpenAI Codex CLI を**自律サブエージェント**として動かし、read-only サンドボックスのまま自分で grep します。グラフ近傍は既定で MCP 経由の道具として渡され、Codex 自身が必要に応じて呼び出します。
- **heuristic**: AI 不要の簡易応答（フォールバック）。

やりたいこと（影響/原因/内容）の判定は**3段ハイブリッド**です: ①ヒューリスティック＋確信度 → ②曖昧なら安価な LLM で分類 → ③なお曖昧なら**本人に確認（確認カード）**。ループにならないよう、確認は一度きりで畳みます。

## 4. データの流れ（取り込み→回答）

```
登録フォルダ ──scan──▶ 文書台帳(documents) ──┬─ 静的解析＋辞書突合（言及エッジ・rag.md本文が対象） ─▶ Neo4j（影響グラフ）
   │                                       └─ 本文（原文 / 派生rag.md） ─▶ Elasticsearch（全文）
   └─ Office → 決定的MD＋RAG正本rag.md（data/derived の md/・rag/）
利用者の問い ─▶ やりたいことの判定 ─▶ 影響=決定的グラフ探索／その他=AI が grep/ES/グラフを反復 ─▶ 答えカード＋出典（原本DL）
```

- 取り込みは**世界単位のクリーン再構築**（古い辺を残さないよう、当該世界のグラフを消してから作り直し）。
- 台帳とグラフは同じスキャンのスナップショットから作るので、根拠に出る文書は必ず台帳に存在します。

## 5. 認証・共有・個人 workspace

認証が有効な環境では、すべての主要画面/API はログインユーザーを確認します。

- **ユーザー**: uid が安定キーです。会話、共有、個人 workspace、監査ログは uid に紐付きます。
- **役割**: `user` は通常利用、`admin` は資料取り込み・ユーザー管理・監査ログ閲覧もできます。
- **セッション**: `sherpa_session` cookie を使い、DB には token hash を保存します。
- **会話共有**: 所有者が招待ユーザーと期限を指定してリンクを発行します。招待されたログインユーザーだけが読み取り専用で開けます。
- **個人 workspace**: `SHERPA_USERS_DIR/{uid}/workspace` 配下に保存します。個人ファイルは台帳基準で grep され、ES/Neo4j には入りません。
- **共有ガード**: 個人ファイルを参照した会話は `contains_personal_workspace` が立ち、通常共有は拒否されます。

詳しい as-built は [06-認証と個人領域.md](../06-認証と個人領域.md)。

## 6. 自己修復（孤児の自動掃除）

参照先の変更・世界の削除・索引/グラフのキー変更などで、**登録世界に属さない派生物**（ES索引・Neo4j のパーティション・派生MDフォルダ）が取り残されることがあります。これを**取り込み・削除・起動の直後に自動で掃除**します（管理操作不要・ユーザ不可視）。

安全のため、次の場合は**何もしません**（誤って正しいデータを消さない）。

1. 登録レジストリ（DB）が確実に取得できないとき。
2. 対象フォルダの列挙が不確実なとき（権限・I/O エラー等）。
3. 派生領域の設定が原本フォルダと重なる誤設定のとき。

→ 実装は `sherpa/reconcile.py`。

## 7. セキュリティの芯

- **社内資料のみが RAG の引用元**。個人の作業領域（workspace）は grep だけで、ベクトル/グラフ索引に入れず、引用元にも出しません。
- **ログインと role で入口を分ける**。資料取り込み・ユーザー管理・監査ログは admin 操作です。
- **個人ファイル参照会話は通常共有不可**。共有する場合は個人部分を伏せる設計に寄せます。
- **外部 AI へは本文テキストのみ送信**、**ファイルは外部に永続化しません**。
- **削除は派生物まで一括伝播**（台帳・派生MD・ES・Neo4j）。**登録元の外部フォルダ（原本）は消しません**（読み取り専用）。取りこぼしは自己修復が回収します。
- 出典の解決は**パス基準・ルート限定**（`..`/絶対パス/範囲外は拒否）。

→ 実行時の権限・サンドボックス・本番ディレクトリは [40-運用](40-運用.md) と [08-実行権限と隔離.md](../08-実行権限と隔離.md)。
