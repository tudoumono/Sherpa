# 90. リファレンス（API・設定・データ）

開発者向けの早見表。詳細は各設計ドキュメント（[../README.md](../README.md) の索引）を参照。

## API（FastAPI）

API サーバーの既定ベースURLは `http://127.0.0.1:8000` です。`SHERPA_HOST` / `SHERPA_PORT` / `SHERPA_UVICORN_WORKERS` で変更できます。

### 認証モード

| モード | 条件 | 挙動 |
|--------|------|------|
| 認証モード | 既定 | `POST /auth/login` が発行する `sherpa_session` cookie が必要。Admin API は `admin` ロール必須 |
| 互換モード | `SHERPA_AUTH_DISABLED=1` | 全リクエストを合成 `admin` として扱う。開発・検証用。通常運用では使わない |

`sherpa_session` cookie は `HttpOnly` / `SameSite=Lax` / `path=/` です。`SHERPA_ENV` が dev/development/未設定以外の場合は `Secure` が付きます。

初期 admin は `uid=admin` / `Administrator` / `admin@sherpa.local` で自動作成されます。初期パスワードは `SHERPA_ADMIN_PASSWORD`、未設定時は `Sherpa2026!` です。`must_change_password=true` の間は `/auth/change-password` などを除き通常APIへ進めません。
新規設定するパスワードは 8 文字以上の半角英数字・記号のみです（全角文字・空白不可）。

### リクエスト規約

- `POST` / `PUT` / `PATCH` は主に `application/json` を受け付けます。
- `POST /workspace/files` は `multipart/form-data` でファイルをアップロードします。
- `GET /chat/stream` は `text/event-stream` の Server-Sent Events を返します。
- `GET /documents/download` と `GET /impact/{aid}/export.xlsx` はバイナリダウンロードです。
- 取込ディレクトリ＝資料フォルダの指定は、多くの API で `world`（world id）です（クエリ/body 共通）。資料フォルダ管理系は path の `{wid}` を使います。旧 `version` パラメータの受理は語彙統一フェーズ2・第2段（2026-07-13）で終了済みです＝送っても黙って無視されます（`world` を使ってください）。
- `scope_paths` は資料フォルダ内のフォルダ prefix です。空なら資料フォルダ全体、未知または不正な prefix は `422` です。

### 全エンドポイント

**エンドポイント一覧の正は起動中サーバーの `/docs`（Swagger UI）と `/openapi.json` です。** パス・パラメータ・リクエスト/レスポンス形は本書では手書き複製せず、起動中サーバーで確認してください（`GET /docs` はブラウザ表示、`GET /openapi.json` はプログラムからの取得向け）。互換モード（`SHERPA_AUTH_DISABLED=1`）では cookie なしで全エンドポイントを利用できます。

`/docs` の見出し（タグ）は次のとおりです: 認証・チャット・トラブルシュート・QA・ナレッジグラフ・会話共有・会話管理・個人ワークスペース・影響分析・文書・管理者:ユーザー管理・管理者:監査ログ・範囲・設定・資料フォルダ(World)管理・システム。

#### 主要フローの curl 例

ログイン→資料フォルダ（world）登録（admin）→ヘルス確認→チャット→影響分析→Excel 出力、の一連の流れです。cookie はファイルに保存して使い回します（`-c` で保存、`-b` で送信）。互換モードではログイン手順（1）を省略できます。

```bash
BASE=http://127.0.0.1:8000

# 1. ログイン（sherpa_session cookie を cookies.txt に保存）
curl -sS -c cookies.txt -X POST "$BASE/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Sherpa2026!"}'

# 2. 資料フォルダ（world）を登録して取り込み（admin 必須）
curl -sS -b cookies.txt -X POST "$BASE/worlds" \
  -H 'Content-Type: application/json' \
  -d '{"path":"/mnt/c/test","label":"test","world_id":"test"}'

# 3. 状態ドット用のヘルスサマリ
curl -sS -b cookies.txt "$BASE/health/summary"

# 4. チャットで質問（社内資料参照ON）
curl -sS -b cookies.txt -X POST "$BASE/chat" \
  -H 'Content-Type: application/json' \
  -d '{"message":"消費税率を変えると何に影響する？","world":"test","knowledge":true,"stream_id":"cli-0001-0001"}'
# stream_id（英数 8〜64 文字・任意の相関ID）は必須。途中で止めるときは POST $BASE/chat/stream/stop に同じ stream_id を送る

# 5. 影響分析を実行（応答の analysis_id を控える）
curl -sS -b cookies.txt -X POST "$BASE/impact/run" \
  -H 'Content-Type: application/json' \
  -d '{"start":"消費税率","world":"test"}'

# 6. 影響分析結果を Excel でダウンロード（{aid} は手順5の analysis_id に置換）
curl -sS -b cookies.txt "$BASE/impact/{aid}/export.xlsx" -o impact.xlsx
```

### 共通エラー

| コード | 意味 |
|--------|------|
| `401` | 未ログイン、またはセッション期限切れ |
| `403` | 権限不足。Admin API や他ユーザーリソースへのアクセス拒否 |
| `404` | 資料フォルダ、会話、ファイル、分析、原本文書が見つからない |
| `409` | 競合。個人ファイルを含む会話の共有拒否、既存の資料フォルダとのパス重複など |
| `413` | 個人ファイルのアップロード上限超過 |
| `422` | `world` / `scope_paths` / uid / 拡張子 / body 形式などのバリデーションエラー |
| `500` | 内部エラー。監査ログ書き込み失敗時は fail-closed |
| `503` | Neo4j、Elasticsearch、LLM プロバイダなど下流が利用不可 |

## 設定（環境変数）

環境変数のひな型は `.env.example`（開発機は `.env` へコピー・本番は `/etc/sherpa/sherpa.env`）。ひな型と**同じ節立て**で並べます。
調整用の細かい値（会話履歴の長さ・検索や取り込みの内部の上限・稼働確認の待ち時間など）はコードの定数で、環境変数では変えられません。
ひな型に行が無い変数も下表には含みます（`SHERPA_DERIVED_DIR` / `SHERPA_USE_FIXTURES` / `SHERPA_ENV` / `SHERPA_DISABLE_EMBED` /
`SHERPA_HOST` / `SHERPA_PORT` など＝必要時のみ設定。説明に「dev/テスト専用」「手動設定しない」とあるものは通常運用では触りません）。

### 2. 初回の起動で一度だけ管理画面の設定へ入る値

画面（システム管理）と同じ値の初回シードです。**初回だけ使われ、以後は管理画面の値が正**（env を書き換えても反映されません）。

| キー | 用途 |
|------|------|
| `OPENAI_API_KEY` / `OLLAMA_URL` | SET-1（2026-08-22）: **初回起動時に一度だけ**システム管理画面の中央設定（`system_settings`）へ取り込まれる。以後の起動では env を読まない＝2回目以降は管理画面（[24-システム管理](24-システム管理.md)「AIプロバイダ（クラウド）」）で管理する。実行時の解決順は「利用者ごとの個人キー（許可時）→中央設定→未設定」（`sherpa/keys.py`） |

| `SHERPA_MCP_LEDGER_REQUIRED_EXTRA` | 調査台帳の完了判定で、各項目に追加で必須にする根拠の種類（カンマ区切り・現状は `source` か空）。`providers/codex/provider.py` がターンごとに、探す範囲にソースがあれば `source` を自動設定する内部変数（**手動設定しない**）。未設定・空なら追加の必須はなく、語彙外の値が混ざっていたら全体を無効（追加なし）として扱う |
| `SHERPA_MCP_LEDGER_REQUIRE_REVIEW` | 調査台帳の完了判定（`ledger_status` の自己確認）が中間の見直し（`ledger_review_put`）を必須にするか（`1`／`0`）。`providers/codex/provider.py` が Codex の標準モード（出力スキーマ v2 かつ MCP 有効）のターンだけ `1` を自動設定する内部変数（**手動設定しない**）。あくまで自己確認の利便性のための値で、実際の完了判定（台帳ゲート）はこの env に関わらず独立に同じ条件で決める |
| `SHERPA_MCP_LEDGER_REQUIRE_CONTINUATION_RESOLVED` | `ledger_status` の自己確認が、台帳に残っている「追加の観点」の義務（`investigation_ledger.pending_continuation_review()`）の解決を要求するか（`1`／`0`）。`providers/codex/provider.py` が、前ターンの `mostly_answered`＋`extra_perspectives` を注入して復元した「続き」のターンだけ `1` を自動設定する内部変数（**手動設定しない**・それ以外のターンは未設定＝要求しない扱い）。義務の有無の判定自体は見直しの列だけから決まる——実際の完了判定（台帳ゲート）はこの env に関わらず独立に同じ基準で決める |
| `SHERPA_MCP_TOOLSET` | MCP サーバが公開するツールの絞り込み（`plain`／未設定）。`providers/codex/provider.py` が管理画面の設定 `codex_mode=plain`（素の Codex モード）のターンだけ自動設定する内部変数（**手動設定しない**）。`plain` のとき `tools/list` は `graph_neighbors`・`ask_user` だけを返し、それ以外の名前の `tools/call` は存在しないツールと同じエラーで拒否する。未設定は従来どおり全ツールを返す |
| `SHERPA_MCP_TOOL_BUDGET_BYTES` / `SHERPA_MCP_TOOL_MAX_HITS` / `SHERPA_MCP_TOOL_WINDOW_CAP` | MCP 子プロセスへ渡すツール結果予算（1件あたり）・ヒット数上限・読取窓のスナップショット（**手動設定しない**・`providers/codex/provider.py::_resolve_mcp_budget_env` が自動設定）。管理画面の基準値＋調べる深さの倍率を解決した実効値で、バイト予算には常に Codex 側の固定天井（1件64KiB）を適用する。累計バイト予算とツール呼び出し回数の上限は Codex 経路では渡さない。モデルの文脈窓と自動圧縮の閾値は指定せず、Codex CLIに任せる |


### 実行構成（チャットに使う AI）

標準では次の3構成だけを見せます（`sherpa/agent_constructs.py`）。やりたいこと（API パラメータ `lens`）は、Codex 調査ではシステムが利用者の意図を判定して自動選択します（影響=`impact`・原因=`troubleshoot`・内容=`qa`・作成=`author`）。簡易は常に内容（`qa`）の検索として扱い、作成は断ります。

| 構成（画面の表示） | 保存値 | 調べ方を決めるのは | 使うモデル |
|---|---|---|---|
| Codex 調査（OpenAI） | `agent=codex`・`codex_model_provider=openai` | Codex CLI 自身（自分で資料を読み、台帳で確かめる） | OpenAI（Azure OpenAI を含む） |
| Codex 調査（Ollama） | `agent=codex`・`codex_model_provider=ollama` | 同上 | Ollama |
| 簡易（検索して答える） | `agent=simple` | Sherpa の道具ループ（最大3往復・1往復あたり道具4回） | 管理者の「簡易回答に使う AI」（OpenAI か Ollama・外部 API の `/ext/v1/answer` と共通） |

- **資料参照は常にON**です（Codex 調査・簡易とも）。画面のトグルも固定され、サーバ側でも強制します。
- 保存された旧い値は、`openai`／`ollama`（API 直結）なら読み取り時に簡易として扱い（保存内容は書き換えない）、`gemini`／`bedrock`／`heuristic`（AIなし）なら「簡易または Codex 調査を選び直してください」と案内して止まります（別の AI へ黙って切り替えない）。
- **Codex 調査（Ollama）には Ollama 0.13.3 以降が必要**です。Codex CLI は OpenAI Responses API
  （`POST /v1/responses`）を使い、Ollama はこのバージョンから対応しました（非stateful のみ）。
  古い Ollama では接続できません。
- Codex 調査（Ollama）の接続先は設定画面の Ollama の URL をそのまま使います（別ホストも指定可）。
  接続先は loopback か管理者が許可した宛先だけです（それ以外は Codex を起動せず未接続として返します）。
- Codex 調査が使えない（CLI が無い・サンドボックスが使えない・接続先が許可されていない・簡易の AI が未設定など）ときは
  理由つきで「未接続」と返し、簡易へは黙って切り替えません。

### 下調べ役（Codex 調査のみ）

Codex 調査の標準モードでは、Codex 本体が観点ごとの「下調べ役」と、結果を確かめる「見直し役」を子として起動できます
（条件を満たすときだけ有効。有効かどうかの判定は `sherpa/providers/codex/sandbox.py::codex_multi_agent_enabled`）。
下調べ役のモデルは管理者が「調査・回答」タブの「下調べ役のモデル」で決めます。**個人設定に下調べの AI の選択欄はありません**
（利用者が下調べの AI を選ぶ仕組みは無い）。

## データモデル（要点）

- **資料フォルダ（world）**: 登録ディレクトリ。`world_id` で識別。レジストリ（PostgreSQL）に `root_path` を 1:1 バインド。
- **文書（documents）台帳**: `doc_id`＝資料フォルダのルート相対パス。範囲メタ（top_scope/phase/category）をフォルダから導出。物理パスは API 非露出。
- **ユーザー（users）**: uid が安定キー。role は `user` / `admin`、status は `active` / `disabled` / `pending`。初期 admin などは `must_change_password` で初回変更を強制。
- **会話（conversations/messages）**: user_id に所有される。共有受領は `origin='received_share'` の読み取り専用ラッパー。
- **共有（conversation_shares/share_invites）**: token hash、有効期限、招待ユーザー、取消状態を保持。
- **個人 workspace 台帳（personal_workspace_files）**: uid と rel_path を保持。ES/Neo4j には入れない。
- **監査ログ（audit_log）**: outcome/reason/severity 等を持ち、hash-chain で改ざん検知する。
- **scope_path**: 資料フォルダ内のフォルダ prefix（検索・分析・出典の絞り込みに効く・**prefix 一致**）。共通部品も対象にしたい範囲は合わせて選ぶ。
- **派生物**: Neo4j グラフ（`world_id` パーティション）／ES 索引（`sherpa-kb-{world}-{hash}`・`_meta.world_id`）／`data/derived/{world}/` 配下の3層（`md/`＝写しMD・`rag/`＝RAG 正本 `rag.md`＋証跡・`ir/`＝中間表現）。grep・ES・グラフはいずれも `rag/` を読む（正本は `rag.md`）。いずれも再生成可能で、孤児は自己修復が掃除。

## グラフの語彙（オントロジー）

ノード種別: Module / Copybook / Batch / DataItem / Table / Document。
関係種別: COPIES / CONTAINS / INVOKES / ACCESSES / DOCUMENTS / CORRESPONDS_TO。

## 運用スクリプトの対応 OS

macOS では標準の bash 3.2・BSD 系コマンドで動くように、GNU のコマンド（`timeout`・`flock`・`setsid`・`sha256sum`・`getent`）が無ければ Python（`scripts/lib/portable_tools.py`）で代わりを務めます。

| 区分 | スクリプト・コマンド |
|---|---|
| macOS でも使える | `make start`／`stop`／`status`／`check-ports`（getent が無ければ Python で名前解決）／`backup`／`restore`／`logs`（短縮 `make l c e`・`make logs help` で一覧。`-m` のメモリ行も）／`prod-check`／`dist`／`doctor`／`diag`、開発用の `scripts/gate-lane.sh`・`gate-integration.sh`。`make sandbox-check` は macOS では「Codex は Seatbelt を使うため Linux 用の確認」と表示して正常終了します |
| Linux 専用（macOS では「Linux 専用」と表示して止まる） | 閉域キット（`make_offline_kit.sh`・`install_offline_kit.sh`・`verify_offline_kit_apt.sh`）、`install-docker.sh`、`setup-runtime-users.sh`、`deploy/systemd` |
