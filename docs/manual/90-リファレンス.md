# 90. リファレンス（API・設定・データ）

開発者向けの早見表。詳細は各設計ドキュメント（[../README.md](../README.md) の索引）を参照。

## API（FastAPI）

API サーバーの既定ベースURLは `http://127.0.0.1:8000` です。`SHERPA_HOST` / `SHERPA_PORT` / `SHERPA_UVICORN_WORKERS` で変更できます。

### 認証モード

| モード | 条件 | 挙動 |
|--------|------|------|
| 認証モード | 既定 | `POST /auth/login` が発行する `sherpa_session` cookie が必要。Admin API は `admin` ロール必須 |
| 互換モード | `SHERPA_AUTH_DISABLED=1` | 全リクエストを合成 `admin` として扱う。開発・検証用。通常運用では使わない |

`sherpa_session` cookie は `HttpOnly` / `SameSite=Lax` / `path=/` です。`SHERPA_ENV` が dev/development/未設定以外の場合は `Secure` が付きます。

初期 admin は `uid=admin` / `Administrator` / `admin@sherpa.local` で自動作成されます。初期パスワードは `SHERPA_ADMIN_PASSWORD`、未設定時は `Sherpa2026!` です。`must_change_password=true` の間は `/auth/change-password` などを除き通常APIへ進めません。
新規設定するパスワードは 8 文字以上の半角英数字・記号のみです（全角文字・空白不可）。

### リクエスト規約

- `POST` / `PUT` / `PATCH` は主に `application/json` を受け付けます。
- `POST /workspace/files` は `multipart/form-data` でファイルをアップロードします。
- `GET /chat/stream` は `text/event-stream` の Server-Sent Events を返します。
- `GET /documents/download` と `GET /impact/{aid}/export.xlsx` はバイナリダウンロードです。
- 取込ディレクトリ＝世界の指定は、多くの API で `world`（world id）です（クエリ/body 共通）。World 管理系は path の `{wid}` を使います。旧 `version` パラメータの受理は語彙統一フェーズ2・第2段（2026-07-13）で終了済みです＝送っても黙って無視されます（`world` を使ってください）。
- `scope_paths` は world 内のフォルダ prefix です。空なら world 全体、未知または不正な prefix は `422` です。

### 全エンドポイント

**エンドポイント一覧の正は起動中サーバーの `/docs`（Swagger UI）と `/openapi.json` です。** パス・パラメータ・リクエスト/レスポンス形は本書では手書き複製せず、起動中サーバーで確認してください（`GET /docs` はブラウザ表示、`GET /openapi.json` はプログラムからの取得向け）。互換モード（`SHERPA_AUTH_DISABLED=1`）では cookie なしで全エンドポイントを利用できます。

`/docs` の見出し（タグ）は次のとおりです: 認証・チャット・トラブルシュート・QA・ナレッジグラフ・会話共有・会話管理・個人ワークスペース・影響分析・文書・管理者:ユーザー管理・管理者:監査ログ・範囲・設定・資料フォルダ(World)管理・システム。

#### 主要フローの curl 例

ログイン→資料フォルダ（world）登録（admin）→ヘルス確認→チャット→影響分析→Excel 出力、の一連の流れです。cookie はファイルに保存して使い回します（`-c` で保存、`-b` で送信）。互換モードではログイン手順（1）を省略できます。

```bash
BASE=http://127.0.0.1:8000

# 1. ログイン（sherpa_session cookie を cookies.txt に保存）
curl -sS -c cookies.txt -X POST "$BASE/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Sherpa2026!"}'

# 2. 資料フォルダ（world）を登録して取り込み（admin 必須）
curl -sS -b cookies.txt -X POST "$BASE/worlds" \
  -H 'Content-Type: application/json' \
  -d '{"path":"/mnt/c/test","label":"test","world_id":"test"}'

# 3. 状態ドット用のヘルスサマリ
curl -sS -b cookies.txt "$BASE/health/summary"

# 4. チャットで質問（ナレッジ参照ON）
curl -sS -b cookies.txt -X POST "$BASE/chat" \
  -H 'Content-Type: application/json' \
  -d '{"message":"消費税率を変えると何に影響する？","world":"test","knowledge":true}'

# 5. 影響分析を実行（応答の analysis_id を控える）
curl -sS -b cookies.txt -X POST "$BASE/impact/run" \
  -H 'Content-Type: application/json' \
  -d '{"start":"消費税率","world":"test"}'

# 6. 影響分析結果を Excel でダウンロード（{aid} は手順5の analysis_id に置換）
curl -sS -b cookies.txt "$BASE/impact/{aid}/export.xlsx" -o impact.xlsx
```

### 共通エラー

| コード | 意味 |
|--------|------|
| `401` | 未ログイン、またはセッション期限切れ |
| `403` | 権限不足。Admin API や他ユーザーリソースへのアクセス拒否 |
| `404` | world、会話、ファイル、分析、原本文書が見つからない |
| `409` | 競合。個人ファイルを含む会話の共有拒否、既存 world とのパス重複など |
| `413` | 個人ファイルのアップロード上限超過 |
| `422` | `world` / `scope_paths` / uid / 拡張子 / body 形式などのバリデーションエラー |
| `500` | 内部エラー。監査ログ書き込み失敗時は fail-closed |
| `503` | Neo4j、Elasticsearch、LLM プロバイダなど下流が利用不可 |

| `SHERPA_HISTORY_CHAR_BUDGET` | 会話継続（履歴priming）: 履歴全体の合計文字予算（既定 6000・トークン計測ツールが無いため文字数で近似） |

AI モデル（OpenAI/Gemini/Ollama/Codex）は個人設定に無く、管理者の「使えるモデル」一覧・選択中のクラウドプロバイダから解決されます。唯一の例外は AWS Bedrock（個人設定にモデル選択が残る）。**Codex の推論強度は既定 `low`** で、個人設定・チャットからの上書きは無く（`SHERPA_CODEX_REASONING` env のみで決まる。lens=author だけ `SHERPA_CODEX_REASONING_AUTHOR`（既定 `medium`）が優先される）、実行時に Codex CLI へ渡されます（`-c model_reasoning_effort=...`）。

### 実行構成（チャットに使う AI）

標準では次の4構成だけを見せます（`sherpa/agent_constructs.py`）。やりたいこと（API パラメータ `lens`）は、システムが利用者の意図を判定して自動選択します（影響=`impact`・原因=`troubleshoot`・内容=`qa`・作成=`author`）。

| 構成 | やりたいことを決めるのは | 使うモデル |
|---|---|---|
| OpenAI | Sherpa の反復ツール検索 | OpenAI API |
| ローカル（Ollama） | 同上 | Ollama |
| Codex（OpenAI） | Codex CLI 自身（自分で grep する） | OpenAI API |
| Codex（Ollama） | 同上 | Ollama |

- **Codex 構成は資料参照が常にON**です（Codex CLI は read-only 実行でも自分でファイルを読めるため、
  「参照オフのつもりで資料を見る」状態を作らない）。雑談は OpenAI / ローカル（Ollama）を選んでください。
- **Codex（Ollama）には Ollama 0.13.3 以降が必要**です。Codex CLI は OpenAI Responses API
  （`POST /v1/responses`）を使い、Ollama はこのバージョンから対応しました（非stateful のみ）。
  古い Ollama では接続できません。
- Codex（Ollama）の接続先は設定画面の Ollama の URL をそのまま使います（別ホストも指定可）。
  接続先は loopback か管理者が許可した宛先だけです（それ以外は Codex を起動せず未接続として返します）。
- `gemini` / `bedrock` は既定で表示しません。`SHERPA_EXTRA_AGENTS` で有効化した場合だけ
  選択肢と入力欄が現れます。`heuristic` は有効化しても選択肢には現れません
  （`SHERPA_AGENT=heuristic` と組み合わせて使う内部フォールバック専用）。

### 下調べ（資料の検索）に使う AI ＝ 費用の節約

資料調査は**読む量が多く、費用の大半が入力トークンで発生します**（実測: 1問で入力 118,000 / 出力 1,000）。
個人設定の「下調べ（資料の検索）に使う AI」で、**読む作業だけを安い AI に任せ、最終回答は選んだ AI が作る**
構成にできます（利用者ごとの設定・管理者の一元管理ではありません）。

| 選択 | 動き |
|---|---|
| 使わない（既定） | 上で選んだ AI が自分で検索する（従来どおり） |
| ローカル（Ollama） | 検索・精読を Ollama が行う（無料）。保存時に接続を確認します |
| OpenAI の低コストモデル | 検索・精読を安いモデルが行う（モデルは個人設定に選択欄がなく、管理者の「使えるモデル」（openai/下調べ）の既定値がそのまま使われる。組み込み既定は `gpt-5.4-mini`（実測でこのモデルは資料を精読できた・下の注記参照）だが、管理者がカタログで変更していればその値になる） |

**「OpenAI」を選んでいるときだけ働きます**（Codex は自分でツールを回すため対象外）。うまく調べられなかった
場合は、黙って通常の方法へ切り替えず、エラーとして知らせます。案内に従って設定を見直すか、
「使わない」に変更してください。

## データモデル（要点）

- **世界（world）**: 登録ディレクトリ。`world_id` で識別。レジストリ（PostgreSQL）に `root_path` を 1:1 バインド。
- **文書（documents）台帳**: `doc_id`＝世界ルート相対パス。範囲メタ（top_scope/phase/category）をフォルダから導出。物理パスは API 非露出。
- **ユーザー（users）**: uid が安定キー。role は `user` / `admin`、status は `active` / `disabled` / `pending`。初期 admin などは `must_change_password` で初回変更を強制。
- **会話（conversations/messages）**: user_id に所有される。共有受領は `origin='received_share'` の読み取り専用ラッパー。
- **共有（conversation_shares/share_invites）**: token hash、有効期限、招待ユーザー、取消状態を保持。
- **個人 workspace 台帳（personal_workspace_files）**: uid と rel_path を保持。ES/Neo4j には入れない。
- **監査ログ（audit_log）**: outcome/reason/severity 等を持ち、hash-chain で改ざん検知する。
- **scope_path**: 世界内のフォルダ prefix（検索・分析・出典の絞り込みに効く・**prefix 一致**）。共通部品も対象にしたい範囲は合わせて選ぶ。
- **派生物**: Neo4j グラフ（`world_id` パーティション）／ES 索引（`sherpa-kb-{world}-{hash}`・`_meta.world_id`）／`data/derived/{world}/` 配下の3層（`md/`＝写しMD・`rag/`＝RAG 正本 `rag.md`＋証跡・`ir/`＝中間表現）。grep・ES・グラフはいずれも `rag/` を読む（正本は `rag.md`）。いずれも再生成可能で、孤児は自己修復が掃除。
