# GraphRAG オントロジー — 影響範囲分析の抽出スキーマ

> 同一性・スコープの一次情報は [03-鏡モデル.md](03-鏡モデル.md)（登録ディレクトリ＝1世界・範囲＝フォルダ prefix・
> 同一性＝パス・即反映）。本書はそのグラフ層の語彙（ノード/エッジ）と抽出方針を規定する。
> 実装: `sherpa/ingest/model.py`（クローズド語彙の定義）／`sherpa/ingest/world_graph.py`（構築）／
> `sherpa/ingest/world_neo4j.py`（Neo4j 反映・影響 traversal）。

> 看板機能「影響範囲分析」（[12-ユースケース.md](12-ユースケース.md) UC-1）の精度の源。

## 0. 設計思想（最優先）

役割分担を1つの基準で切る:

- **事前計算（グラフ）に残すのは決定的（再現100%）に計算できる構造だけ**。「この変数を変えたら
  影響するソースを漏れなく」は毎回1万ファイルを grep できない以上、事前計算しかできない仕事
  （網羅性＝recall）。
- **意味を読む仕事（文書の文意・業務語とコード名の対応）はクエリ時のエージェント**（LLM＋ツール）
  に任せる。その場で読めば常に最新で、聞かれた分しかコストがかからない。
- 帰結: グラフは**静的解析（アナライザ・不変・[17-開発の教訓.md](17-開発の教訓.md) の5箇条）が出す
  骨格構造**と、**アナライザの定義索引を辞書として文書テキストと機械的に突合した言及**の2つだけで
  構成する。LLM でグラフへ意味を書き込む機構（旧・意味層フル抽出／業務語↔コード自動橋渡し）は
  持たない——全ノードは常に静的解析由来（`extraction_method` は事実上 `static` のみ・「確実／要確認」
  のような信頼度判定は存在しない）。

## 1. ノードラベル（クローズド・6種）

`NODE_LABELS`（`sherpa/ingest/model.py`）:

| ラベル | 説明 / 例 | 抽出元 |
|--------|-----------|--------|
| `Module` | プログラム/クラス/関数（COBOL PROGRAM-ID, `TAXCALC`） | 静的（CALL/PROGRAM-ID） |
| `Copybook` | COBOL コピーブック（共通データ定義）／網羅性の源 | 静的（COPY） |
| `Batch` | ジョブ／ジョブネット（日次締め）。JCL のジョブ/ステップ | 静的（JCL） |
| `DataItem` | カラム/コピーブック項目（`TAX-RATE`） | 静的（コピーブック定義） |
| `Table` | RDB テーブル/VSAM/データセット | **計画枠**（SQL/FILE 静的解析は未着工・producer ゼロ・語彙のみ先置き） |
| `Document` | 取り込み対象の資料（設計書・帳票定義書等）。`documents` 台帳と 1:1（根拠・DL） | 取り込み時に確定 |

業務概念（旧: `Parameter`/`BusinessRule`/`Function`/`Screen`/`Report`/`Standard`/`Incident`）は**撤去済み**
（§7 退役リスト参照）。業務語の入口はクエリ時のエージェントが担う（§5）。

## 2. エッジ型（クローズド・5種＋世代跨ぎの対応1種）

`EDGE_TYPES`（`sherpa/ingest/model.py`）+ `CORRESPONDS_TO`（Neo4j 反映時のみ許容・`world_neo4j.WORLD_EDGE_TYPES`）。

規約: **`A -[依存]-> B` は「A が B に依存する」**。影響分析は incoming（逆向き）を推移的にたどる
＝「B が変わると、B に依存する全部が影響」。

| エッジ | 向き（依存元 → 依存先） | 例 | 影響たどり |
|--------|------------------------|----|-----------|
| `COPIES` | Module → Copybook | COBOL COPY | ○ |
| `CONTAINS` | Copybook → DataItem / Module → Module（同一ファイルの入れ子） | 構造内包の一般形 | ○ |
| `INVOKES` | Batch/Module → Module | **実行・利用依存の一般形**: CALL・ジョブ実行・継承/実装・宣言型参照。細分はエッジ属性 `via`（`call`/`extends`/`implements`/`field_type`/`inject`/`include`/`import`/`copy`/`mention`・既知値は `analyzers._base.KNOWN_VIA` が管理）で持つ——**エッジ型は増やさない**（型は閉じ属性で開く） | ○ |
| `ACCESSES` | Module → Table/DataItem | DB/ファイル読み書き | **計画枠**（`Table` と同様 producer ゼロ・語彙に先置きのみ） |
| `DOCUMENTS` | Document → 任意ノード | 資料が対象を記述／言及する（**根拠**） | ×（根拠として添付。`via="mention"` は下記§5の言及エッジ） |
| `CORRESPONDS_TO` | 同名ノード間（世代を跨ぐ） | 世代違いの対応表示 | ×（producer 未実装・語彙のみ） |

> 影響 traversal（`world_neo4j._IMPACT_REL`）は **`COPIES\|CONTAINS\|INVOKES\|ACCESSES`** のみを辿る
> 決定的な構造たどり。`DOCUMENTS`/`CORRESPONDS_TO` は根拠添付・対応表示の**専用エッジ**で traversal には乗らない。

**制度化された例外（世代を跨いでよい2エッジ）**: 鏡モデルの「構造リンク（COPIES/CONTAINS/INVOKES）は
同一 top_scope（世代）内の最近傍のみ」という規律（[03-鏡モデル.md](03-鏡モデル.md)）に対し、`DOCUMENTS`
（`via="mention"`）と `CORRESPONDS_TO` は世代を跨いでよい——世代の選択（「2025年A案件だから12月版」）は
フォルダ名の解釈であり、クエリ時のエージェントに委ねる（範囲フィルタで絞れる）。

## 3. 共通プロパティ

**ノード**: `cid`（canonical_id）, `label`, `name`, `world_id`, `path`, `value`（定数値等・任意）,
`status`（`active` | `deprecated`＝明示廃止 | `hidden_candidate`＝隠し検出の低信頼候補）,
`top_scope`/`phase`/`category`（範囲メタ・フォルダから導出）。

`cid` はパス修飾（同一性＝パス・[03-鏡モデル.md](03-鏡モデル.md)）:
```
{label.lower()}:{world_id}:{rel_path}#{name}          // ファイル由来（Module/Copybook/Batch/DataItem/Table）
document:{world_id}:{rel_path}                          // Document（同一性＝パスのみ・表題は使わない）
```

**エッジ**: `via`（INVOKES/CONTAINS/DOCUMENTS の細分・§2）, `status`。

来歴（`source[]`）は**静的由来のみ**（LLM 由来は無い）: `{ doc_id, file, line, evidence_text }`。
ソース（COBOL/JCL/Copybook）も必ず `documents` 台帳に1行登録し（doctype=cobol/jcl/copybook）、
`doc_id`＋`line` で原ファイルに解決して DL する。

影響分析は **`active` を既定**、`deprecated`/`hidden_candidate` は除外（`include_deprecated=true` で参照可）。

## 4. 取り込み（静的解析のみ・3パス）

**トラック S（骨格＝Pass1/Pass2）**: COBOL/JCL/コピーブックを**確定的にパース**して構造ノード/エッジを
生成する（対応済み方言・構文に対して再現性100%。未対応方言・未対応構文は自動フォールバックしない
——不可視な劣化として対応表で可視化するに留める・この方針は変更しない）。

| ソース構文 | 生成 |
|-----------|------|
| `PROGRAM-ID` | `Module` ノード |
| `COPY xxx` | `Module -COPIES-> Copybook` |
| コピーブック項目定義（01/05レベル） | `Copybook -CONTAINS-> DataItem` |
| `CALL 'PROG'` | `Module -INVOKES(via=call)-> Module` |
| JCL ジョブ/ステップ | `Batch` ＋ `Batch -INVOKES-> Module` |
| `EXEC SQL` / `SELECT/READ/WRITE` / FILE SECTION | （計画枠・未着工）将来 `Module -ACCESSES-> Table/DataItem` |

**トラック M（言及＝Pass3・§5）**: Pass1 の定義索引をそのまま辞書として資料文書の本文と突合し、
`Document -DOCUMENTS(via="mention")-> コードノード` を張る（LLM ゼロ）。

**マージなし**: 旧「静的＋LLMの2トラックを名寄せで統合」は撤去。骨格（S）と言及（M）は最初から
同一グラフの別エッジ種別として共存し、統合処理を必要としない。

## 5. 言及エッジ（辞書突合）— 業務語↔コードの入口

業務パラメータ↔コード項目の橋渡し（旧 `REALIZES`・LLM 提案→承認）は撤去済み。代わりに:

1. **辞書**: Pass1 が作る `(label, name) -> [rel_path...]` の定義索引を**そのまま**辞書として使う
   （予約語除外は不要——辞書の材料は定義そのものなので、名付けられたものしか入らない）。
2. **突合**: 文書テキストを識別子形トークン（`[A-Za-z0-9_-]+` の最大連続・1パス）に分解し、
   辞書と**トークン全体一致**で照合する（部分文字列検索はしない）。
   - **完全一致・大文字小文字を区別**（識別子は転記される値のため。`normalize_code_name` の
     `upper()` は使わない——`DATA`/`data` のような誤リンクは逆引きを汚染するため fail-closed）。
   - **長さ下限4文字**（`SHERPA_MENTION_MIN_LEN` で調整可）。
   - **辞書内で一意な名前だけ張る**（同一世代内に同名複数定義＝曖昧＝張らない。名前解決 `_resolve_nearest`
     と同じ流儀）。世代を跨いだ同名は§2の例外どおり**全世代のノードへ**張る（世代の選択はクエリ時の
     エージェントに委ねる）。
3. **入口**: 「消費税率を変えたい」のような業務語のクエリは、エージェントが文書を grep してコード名
   （`TAX-RATE` 等）を発見し、そのコード名でグラフへ入る——事前橋渡しへの依存を下げる。

実装: `sherpa/ingest/world_graph.py::_mention_pass`（`build_world` の Pass3・`MENTION_SCHEMA_VERSION`
で仕様版を管理）。対象文書は `branch=="office"`（資料文書）のみ、`branch=="source"` は対象外。

## 6. 影響分析クエリ（recall優先・経路を返す）

```cypher
MATCH (start:Entity {cid: $cid, world_id: $world})
MATCH path = (affected:Entity)
  -[r:COPIES|CONTAINS|INVOKES|ACCESSES*1..8]->(start)
WHERE ( $include_deprecated OR coalesce(affected.status,'active') = 'active' )
  AND ( $include_deprecated OR all(e IN r WHERE coalesce(e.status,'active') = 'active') )
RETURN labels(affected)[0]                          AS 種別,
       affected.name                                AS 対象,
       [n IN nodes(path) | n.name]                  AS 経路    // ← なぜ影響するか
```
- 各 `affected` に `Document -DOCUMENTS->`（`via="mention"`含む）で**根拠設計書＋DLリンク**を添付できる
  （traversal には乗せない・別クエリで根拠添付のみ）。
- 深さ上限は recall とノイズのバランスで調整。
- **「確実／要確認」のような信頼度による分岐は無い**（全ノードが静的解析由来＝同格）。
  grep 共起による「推定影響（presumed）」は本 traversal とは別枠の補助表示として残る。

## 7. 退役した概念（復活させない）

以下は**撤去済み**。詳細な経緯は開発リポジトリ内部の資料と Git 履歴にある
（本書には残さない）:

- 意味層フル抽出（`graph_extract.extract_world`・チャンク単位 LLM 抽出・2パス名寄せ）
- `concept_propose`/`auto_bridge`（業務語↔コードの LLM 提案→承認／自動橋渡し）と `concepts.json`
- 概念ラベル7種（`Parameter`/`BusinessRule`/`Function`/`Screen`/`Report`/`Standard`/`Incident`）
- 概念エッジ7種（`USES`/`REFERENCES`/`IMPLEMENTED_BY`/`PRODUCED_BY`/`CONFORMS_TO`/`RELATES_TO`/`REALIZES`）
- ノードの確信度判定（`extraction_method`＝`static`/`llm`/`both` の3値・「確実／要確認」表示）

## 8. バージョン → 鏡モデルに置換（[03-鏡モデル.md](03-鏡モデル.md) が一次情報・「版」概念は撤去）

影響は **world_id ＋ scope_prefixes** で絞る（世代＝トップフォルダ）。履歴/差分は Git を検討事項。

## 9. 残論点（実装時に詰める）

1. **静的解析パーサの選定**（COBOL 方言・JCL）。未対応方言・未対応構文の可視化強化。
2. **`Table`/`ACCESSES`（SQL/FILE 静的解析）・`CORRESPONDS_TO`（世代対応の producer）の着工判断**
   （現状は語彙のみ先置き・実装なし）。
3. **言及エッジの一意判定しきい値**（長さ下限4文字・大文字小文字区別）の実地チューニング。
4. **リフレクション型（クラス名が文字列リテラル）の値側トークン突合**（将来対応）。
5. **設定ファイル（.properties/YAML）アナライザ**（将来対応・「1種別1本」の増設方針に従う）。
