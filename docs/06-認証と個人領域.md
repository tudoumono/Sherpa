## 0. 位置づけ・不変条件
- **認証は既定ON**：未設定でもログイン必須。`SHERPA_AUTH_DISABLED=1` の明示時だけ開発・検証用の互換モード（合成 admin）。
- **uid が安定キー**：会話・共有・workspace・監査は uid に紐付く（将来の SSO 差し替えでも上物無改修）。
- **個人ファイルは共有 RAG に入れない**：`personal_workspace_files` 台帳は ES/Neo4j 取り込み対象に**絶対含めない**。grep のみ。
- **共有 KB は読取専用**：登録 world 配下は agent から書込不可（アプリ層＋OS所有権の多層防御）。

## 1. 認証・ユーザー（`sherpa/auth.py`・`sherpa/store.py`・`sherpa/api.py`）
- **パスワード**：pbkdf2 ハッシュ。**セッション**：cookie `sherpa_session`（sha256 ハッシュを DB 保存）。**role**：admin / user。
- **bootstrap**：`admin` が無ければ自動作成。初期パスワードは `SHERPA_ADMIN_PASSWORD`、未設定時は `Sherpa2026!`。`must_change_password=true` で初回変更を強制。
- **無効化が正式**（削除しない）：`users.status='disabled'`。管理 UI（`web/admin-users.*`）で作成・無効化・**他ユーザーのパスワードリセット**（`PATCH /admin/users/{uid}`）。
- **uid 制約**：slug（`^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`）を API＋**DB CHECK**（`users_uid_format`・NULL も拒否）で二重に。
- **読取/クエリ系エンドポイントは認証ゲート**（認証ON時）。ログイン壁は `web/nav.js`（401→`/ui/login.html?next=`）。
- **将来**：社内 SSO（Entra/Google/SAML/OIDC）を `auth_identities(provider,subject→uid)` フックに逃がす。

## 2. 会話共有（`sherpa/api.py` §共有・`sherpa/store.py`）
- **リンク発行 → クリック → 権限判定（ログイン＋招待＋有効＋所有）→ 受領共有ラッパー**（`origin='received_share'`・`source_conversation_id` 参照・read_only）。本文は元会話から読む（コピーしない＝取消/期限が効く）。
- **個人ガード**：`conversations.contains_personal_workspace=true` の会話は共有不可（**409**）。受領共有 read 時も元会話のフラグを再確認（二重防御）。
- **sanitized share snapshot**（`sanitize=true`・§Phase2 実装済）：個人参照会話を**凍結コピー**で共有。`store.create_sanitized_snapshot` は **denylist コピーでなく allowlist 再構築**:
  - **per-turn 個人フラグ**（`messages.personal`・chat_service が個人ヒット/Codex書込/個人facts のターンに設定）＝**個人ターンは質問も回答も伏字**。
  - 非個人ターンの `answer` は KB 由来の allowlist（headline/data/summary/scope/KB sources のみ）で再構築。**title は固定文言**・**route/trace は常に落とす**・lens は enum allowlist。
  - `origin='sanitized_snapshot'`・read_only・`contains_personal_workspace=FALSE`（受領 guard を通る）。会話一覧に非表示。`sanitize=true` は flag に関係なく必ず snapshot（in-flight 対策）。
  - **限界**：利用者が**手入力**した個人情報（システム非検出）は伏字対象外＝opt-in の共有者責任。

## 3. 個人ワークスペース（`sherpa/store.py` 台帳・`sherpa/api.py`・`sherpa/chat_service.py`）
- **台帳**：`personal_workspace_files`（uid/rel_path/original_path/sha256/status/expires_at）。実体は `SHERPA_USERS_DIR/{uid}/workspace/{outputs,tmp,files,authoring}`。
- **grep は台帳基準**（W1）：`live_workspace_rel_paths`（status='uploaded'）だけを対象＝論理削除の FS 残骸がヒットしない。許可拡張子＝grep 対象を一元化（W2）。
- **TTL 自動掃除＋孤児 GC**（W4・`api._sweep_expired_workspace`＋`_gc_orphan_workspace_files`・起動時＋ポーラループ）：fail-safe（DB 不可なら削除しない）／base-confined／symlink 拒否／advisory lock で upload と直列化／**無効化ユーザー・unknown ユーザーは保持**／共有 RAG 非関与。
- **チャットの個人参照トグル**（Feature B・`web/chat.js`・既定OFF）：ON で current user の個人ファイルも grep し「個人ファイル内ヒット」として facts/citation に載せる（本人のみ・ES/Neo4j 非索引）。ON で拾うと会話に `contains_personal_workspace` が立つ＝共有ガード発火。

## 4. Codex の個人書込サンドボックス（Feature A・`sherpa/agents.py` CodexProvider）
- **読取封じ込め＝permission profile 方式**（`-s workspace-write` の読取全開を廃止・実機実証済）。既定ON・`SHERPA_CODEX_SANDBOX=0` でフォールバック。
  - KB=読取専用／authoring=読書／`:root=deny`（他人領域・秘密・任意 FS の読取遮断）／shell network 遮断／**env 洗浄**（DB/ES/KB creds を Codex プロセスに渡さない）。
  - creds は per-request `CODEX_HOME/config.toml`(0600) 内に閉じ（`:root=deny` で model-shell から不可視）、`/proc/<mcp_pid>/environ` も到達不可を実機確認。
  - symlink 拒否（authoring/workspace）・fail-closed・process group kill・`.tmp` は台帳登録除外。
- **Office 生成**：python-docx / python-pptx / openpyxl。生成物は `authoring→files` に移動して台帳登録（既存 grep/TTL/DL 機構に乗る・移動＋登録は advisory lock 内）。
- **落とし穴と recipe の詳細** → 開発リポジトリ内部の調査記録を参照。

## 5. 監査ログ（`sherpa/store.py` `audit()`/`verify_audit_chain()`・`sherpa/api.py`）
- **拡張列**：outcome/reason/severity/request_id/session_id/ip_hash/user_agent/before_state/after_state（redaction 二重）。閲覧は `GET /admin/audit`（admin・閲覧自体を監査）。
- **記録対象**：login(_failed)/logout・user 作成/無効化/パスワードリセット・share 作成/拒否/受領/取消・workspace upload/delete・document download・settings 更新・**world 削除（fail-closed pre-event）**。
- **改ざん検知 hash-chain**（§Phase2）：`prev_hash`/`entry_hash`＋`audit_chain_head`（anchor: last_id/last_hash/cnt/chain_start_id）。`audit()` は advisory (xact) lock 内で **INSERT→RETURNING（DB格納値）→hash→UPDATE→head 更新**を1tx（JSONB/tz 往復に強い）。`verify_audit_chain()`（`GET /admin/audit/verify`）が**改ざん・並べ替え・末尾削除(truncation)・NULL偽行注入・anchor 欠落**を検出。
- **残**：anchor も同一 DB 内 → DB superuser への完全防御には **head の外部署名/エクスポート**が別途必要。

## 6. 多層防御（OS 層）
- 本番は **`sherpa-ingest`/`sherpa-agent`/`sherpa-api`＋`sherpa-workspace` グループ**で所有権分離（`scripts/setup-runtime-users.sh`・冪等/dry-run/verify）。kb は sherpa-ingest 所有・group 書込なし＝**agent は FS レベルで kb を書けない**。permission profile（アプリ層）が破れても所有権で他人領域/kb を書けない。詳細 [08-実行権限と隔離.md](08-実行権限と隔離.md)。
